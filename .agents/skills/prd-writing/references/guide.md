# PRD記述ガイド

## 目的

PRDは、誰のどの問題を、どの範囲で、どの成果を目指して解決するかを合意する文書である。実装方法ではなく、製品として必要な振る舞いと判断基準を記述する。

## 記述基準

### ユーザーと課題

- 実際に価値を受け取るユーザー群を区別する。
- 現在の行動、困りごと、制約、期待する変化を具体化する。
- 属性を推測で作らず、意思決定に必要な情報だけを記載する。

### 目標と成功指標

- Product Goalsは望む成果を記述する。
- 成功指標は測定対象、測定方法、達成条件、必要なら期限を含める。
- 根拠のない数値を置かず、未確定の目標値は未決事項とする。

### スコープと優先度

- P0: MVP成立または移行完了に不可欠な要件。
- P1: P0完了後の品質や運用を強化する要件。
- P2: 将来検討する改善候補。
- In ScopeとOut of Scopeを対で書き、今回実施しない内容を明示する。

### 機能要件

各要件に利用者、目的、期待する振る舞い、例外、優先度、受け入れ条件を対応させる。

```markdown
### [要件名]

- 利用者: [対象]
- 目的: [解決する課題]
- 振る舞い: [期待する結果]
- 例外・停止条件: [該当する条件]
- 優先度: P0 / P1 / P2

受け入れ条件:
- [ ] [観察または検証できる条件]
```

### 非機能要件

性能、信頼性、セキュリティ、アクセシビリティ、プライバシー、オフライン要件など、製品に関係する項目だけを測定可能に記述する。

## 品質チェック

- 用語が初期要件と一致している。
- 全P0要件に検証可能な受け入れ条件がある。
- 目標と機能を混同していない。
- 実装技術や画面詳細を先回りして固定していない。
- 対象外と未決事項が明示されている。
