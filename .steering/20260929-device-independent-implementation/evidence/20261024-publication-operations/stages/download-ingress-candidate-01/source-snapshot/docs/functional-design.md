- 対象: FrameRelay初期版の全P0要求（FR-01〜17、NFR-01〜04）。要求の正本は、補足R2を含め2026-09-25に全体承認され、2026-09-26の明示回答を補足R3として反映した[プロダクト要求定義書](product-requirements.md)（以下PRD）。R3は全体承認を維持する。初期要件へ要求の更新先を戻さない。
- 確定変更: [バックエンド連携仕様](ideas/20260928-backend-integration.md)と[実機なし先行実装仕様](ideas/20260929-device-independent-implementation.md)（DI）の限定差分を適用する。背景動作・状態同期・動画別操作、削除後の表示・写真権限・ズーム操作を再度の未合意へ戻さず、PRDの全要求・品質・安全条件を維持する。

## 利用者フロー

R3で確定した操作ごとの対象粒度は次のとおり。複数選択では本人がまとめて開始した対象集合を固定し、D8に従って動画ごとの操作・条件・結果を追跡する。内部は順次処理でよく、複数同時通信を要件にしない。

| 操作 | 初期版の粒度 | 維持する条件 |
| --- | --- | --- |
| 原本転送 | 複数選択してまとめて開始 | Wi-Fiでの開始受理、動画別の送信と保存・全内容検証の区別 |
| 軽量版の「写真」保存 | 複数選択してまとめて開始 | 動画別の取得・登録結果、重複防止と一時コピー解放 |
| 条件を満たす原本の容量整理 | 複数選択してまとめて実行 | 各実行直前の保存・検証・明示確認・対応・失効・排他の照合 |
| 軽量プレビュー再生・明示確認 | 1本ずつ | 実際に再生した同じ版への本人の明示確認。複数選択を確認に代用しない |
| 不要動画の破棄 | 1本ずつ | 本人が各対象・消失リスクを確認して明示指示。一括破棄なし |

選択しただけでは開始指示にならない。開始受理後の順番待ちは指示済みとし、後から撮影・表示・選択された動画を自動追加しない。転送・取得等の個別動画の失敗は残して独立した残件を続行し、回線・認証・Mac容量不足等の共通問題は影響する処理を待機させる。個別停止/再開/キャンセルと開始済み動画通信の全件停止を用意する方針は確定済みであり、処理順・具体的な停止UI等はU1・U3の残件とする。

### F1 起動から録画・次の撮影へ

通常撮影は試験票を要求せず、撮影設定→REC/STOP→アプリ内保存→一覧から既存の原本再生へつなぐ。探索用の試験参照や試験時間上限を通常撮影の開始条件にしない。保存結果の確定後は原本との内容対応を照合して一覧を更新し、保存分類・内容対応・再生可否を別々に示す。撮影を準備できない端末や権限拒否時も、ライブラリへの入口を維持する。

1. 保存済み撮影設定を読み、現在の端末・カメラ・形式の対応情報と照合する。カメラ・マイク・内部保存先を準備し、入力有効性を確認する。初回権限取得、通常起動、復帰を区別する。
2. 撮影画面に実適用値と準備状態を出す。WBはAuto。補正は初回の標準相当候補または前回選択を対応確認後に適用する。非対応・未確認の場合は制約と選択肢を示し、代替を勝手に適用しない。
3. 人物・ND解析の完了を待たず、必要な記録条件が整えばRECを受け付ける。REC受付で動画通信の再開を閉じ、端末上の送受信を一時停止する。サーバー応答や未完了のサムネイル生成を待つことを開始条件にしない。
4. REC時点で得られているWBを記録用に固定し、音声付き記録の開始を確認して録画中表示へ移る。WBの安定待ちは入れない。REC受付・記録開始・最初のフレームは別の時点として測定する。
5. 録画中は音声メーター・入力有効性と実適用値を継続表示する。ズームは目標選択→構図予告→本人の明示的な移動開始→目標自動停止/途中停止とし、ズーム停止とREC停止を分ける。対応するレンズ切替・WBの明示合わせ直しを扱う。RECのSTOPまたは確認済み音声障害・記録不能で記録停止へ進む。
6. 最後の記録フレームまでWB固定を保ち、記録終了後に待機用Autoへ戻す。ファイルの確定・照合を行い、正常保存・部分保存・結果不明・失敗を通知する。録画停止を保存成功とは扱わない。
7. 推奨操作案U1では撮影画面に留まり、保存結果を控えめに通知する。通常撮影では保存結果のcommit応答まで次RECを抑止し、その後は記録先・音声等の準備条件で判断する。前クリップの内容対応の照合・一覧更新・サムネイル等の後処理は分離し、完了待ちを次RECの条件にしない。内容対応と一覧更新は画面離脱や次の撮影でも原本ごとに処理し、後処理の失敗を次クリップの撮影障害として表示しない。未完了保存は保持し、必要な準備中は理由を表示する。連続撮影時の負荷・次RECの速度は実機検証対象とする。

### F2 手動転送からRec.709軽量版生成へ

1. ライブラリの原本が存在する項目を複数選択して「Mac miniへ転送」をまとめて指示できる。新規の指示はWi-Fi接続時のみ受理し、不在時は接続案内を出して、復帰時に開始する予約を作らない。動画別に対象を照合し、正常保存は通常の対象、部分保存は再生可能性と対象ファイルの確定後にその状態を示して扱う。保存中・結果不明・失敗中のファイルはそのまま送らず、先にローカル照合する。
2. 受理した対象集合と動画別の操作IDを保持し、各実行時に認証・接続先、録画・保存との競合、本人の停止/キャンセル状態とWi-Fiの継続を確認する。順番待ちも開始指示済みとし、受理後のWi-Fi切断等で実行できなければ具体的な待機理由を出す。本人が止めていない未完了通信はS4の条件再確認後に自動再開する。
3. 原本の同一性と転送操作IDを付けて送信する。送信完了後もMac miniの保存・整合性検証結果が確定するまで「保存検証待ち」とする。再送・再照会は同一操作を識別し、別原本を作る操作と分ける。
4. Mac mini側で原本の保存・検証が成功した場合だけ、自動でRec.709軽量版生成へ進む。未変換の圧縮版を完成品へ昇格させない。原本は改変せず、生成失敗は保存検証の成功と分けて表示する。
5. 生成済み版の原本ID・映像ID・変換情報を受け取る。初回生成と、確認済みV1に対する新版V2の生成・差し替えを分け、後者はS5へ進む。iPhoneのRECでMac miniの開始済み変換は止めない。
6. 動画別に送信、保存検証、変換の成否・結果不明・待機・未処理を表示する。一部の成功を全対象の成功にせず、個別失敗に依存しない別動画は続行する。共通問題の待機と分け、再開で対象集合を増やさない。

固定queued受付の通常導線は、詳細の単数転送と既存の複数転送から、同revisionの一覧が持つ選択原本/保存commit・現登録・store UUID・親/全子IDを最初のawait前に固定する。初期native Wi-Fiを確認できない場合は開始予約を作らない。正常保存と原本対応・存在/byte数等を最終記録時に動画別に再判定し、部分/不明/失敗・不在・失効/削除中・重複等は理由付き未処理に残して、適格な別動画を受け付ける。正常保存以外の実送信は許可しない。固定全集合を減らしたり後から対象を足したりせず、受付をMac miniの保存や通信成功として表示しない。

### F3 軽量プレビュー確認と容量整理

1. 項目の「Rec.709軽量版を確認」から、1本ずつ対象原本・変換版・映像IDを固定して再生する。「写真」保存用と同じMac mini生成軽量版を全体の一時取得を待たずに確認できるストリーミングを第一候補とする。Wi-Fi・録画/保存優先・一時使用量管理に従い、成立性はI3/I6で検証する。取得済みのローカル動画はオフラインでも再生できる。
2. 実際の映像が再生された同じ版に対して、1本ずつ「この軽量版の内容を確認した」を押す。全体の軽量版ダウンロード、全編再生や一定秒数の視聴を条件にしない。再生開始失敗、単なるサムネイル表示、撮影プレビュー、未変換版、複数選択は確認にならない。ストリーミングの再生到達を原本全内容の保存・整合性検証や「写真」保存の代用にしない。
3. 原本・映像ID・確認世代の対応を再照合し、確認記録を永続保存する。記録保存の確定後だけ「明示確認済み」とする。別版へ変わっていた場合は古い操作を反映しない。
4. 保存検証・Rec.709版・有効な確認・ローカル原本の対応から動画別に容量整理可能性を判定し、条件を満たす原本を複数選択して「iPhone原本を容量整理」をまとめて指示できる。削除前の対象表示では動画別の撮影日時・サムネイル・サイズと最後に取得したMac mini保存検証の記録を示す。
5. 本人が指示した対象集合を固定し、各削除の実行直前に端末内の最新の保存・検証・明示確認・対応・失効状態と排他を再照合する。選択後に失効した対象は削除せず、破棄へ自動移行しない。Mac mini再接続・再生・「写真」保存・追加バックアップ・高品質版生成を追加条件にしない。
6. S6の手順でローカル原本だけを削除・照合し、動画別に削除済み・未削除・確認が必要・未処理を表示する。容量整理成功後も通常一覧の同じ項目と管理記録を残し、「原本なし」、軽量版の取得/再生可否、明示確認、「写真」保存を別々に示す。未取得の軽量版をオフライン再生可能にせず、削除結果不明も通常の作業導線で要照合とする。Mac mini・「写真」は連動削除しない。オフライン時は「保存検証の最終記録に基づく操作」であり、Mac mini原本の現在の存在を照合した表示にしない。

### F4 同じ軽量版を「写真」へ保存

1. ユーザーが複数の動画を選択し、対象軽量版の「写真に保存」をまとめて指示できる。新規の指示はWi-Fi接続時のみ受理し、不在時は接続案内を出して開始予約を作らない。容量整理の前後どちらからも開始できる。DI-06に従い、本人の保存操作に必要な時点で追加権限（add-only）を求め、拒否時は設定変更等を案内する。撮影起動時に一律要求しない。
2. 受理した対象集合と動画別の操作ID・撮影/変換版/映像の対応を固定し、各動画の登録状態を確認する。登録済み、登録中、結果不明を無条件に新規追加しない。不明結果等の照合が必要な時だけ対象と理由を示して読み取り権限（readWrite）を案内し、拒否・限定・未発見・対応不明は未保存と断定せず要確認を維持する。権限不足で関係のない撮影を止めない。
3. Wi-Fiで対象版を一時取得する。内部は順次処理でよく、受理後の順番待ちや切断による待機も開始指示済みとしてS4の条件付き自動再開を適用する。取得完了と登録成功を分け、登録操作の意図を永続保存してから「写真」へ追加する。正当に開始した操作で取得済みの版をローカルに登録する段階には、Wi-Fiの継続を要求しない。撮影日時を維持し、取得日時で置き換えない。
4. 動画別に登録結果・アセット対応を保存したら成功を表示し、使用中でない一時コピーを解放する。取得・登録の失敗/結果不明/未処理も動画別に示す。通信の自動再開を結果不明の登録の自動再実行へ拡張せず、利用者が後から「写真」で削除しても自動復活させない。

### F5 不要なiPhone原本を破棄

1. ユーザーが1本ずつ項目の別操作「不要な原本を破棄」を開く。複数選択による一括破棄は行わない。容量整理が不可でもこの操作へ自動的に誘導・切替しない。
2. 対象の撮影日時・サムネイル・サイズ、iPhone原本だけが対象であること、転送・保存検証の状態を示す。未転送・検証不明等では「Mac miniへの保存が確認できないため、この原本を失う可能性があります」と明示する。部分保存の場合はその状態も示す。
3. 対象と消失リスクを本人が確認して「このiPhone原本を破棄」を明示する。軽量プレビューの確認ボタンとは別のイベントとし、FR-13の確認記録を作らない。
4. 録画・保存・転送等との競合をS6に従って解消する。競合の解消中に対象や状態が変わったら古い確認で自動実行せず、新しい表示で操作を受け直す。
5. ローカル原本の削除結果を照合して「破棄済み」「未削除」「確認が必要」を区別する。同じ対象・破棄目的・操作に対する実ファイル不在と結果commitを照合できたものだけ履歴へ移す。未削除・未処理・不明は通常の作業導線で要照合等を表示する。履歴は復旧・照合・重複防止の管理記録であり、原本を移動・隠蔽して保持するゴミ箱にしない。Mac mini・「写真」を連動削除せず、保存検証や軽量版確認の状態も変更しない。

DI-05に従い、容量整理後も通常一覧の同じ項目で原本なし・軽量版の取得/再生可否・明示確認・写真状態を独立表示する。再生元の選択UIや優先順はU1・U2の残件とし、確認再生はR3のストリーミング第一候補を維持する。「写真」での鑑賞は独立した操作とし、読み取り許可がないことを容量整理不可へ結び付けない。再生可能なローカル媒体がなくオフラインなら再生できない理由を示すが、有効な記録による容量整理へWi-Fi・再生・写真保存を追加条件にしない。

S28は完全取得済みlocal軽量版の消費側を、local項目/remote保存原本行からの1本ずつの再生へ接続する。現在の登録・公開版と成功した配布記録、論理原本とのexact対応、全媒体内容と実ファイルを再照合し、原本本体が不在でも対応する軽量版を扱う。Wi-FiやMac miniへの接続は不要で、未取得媒体や欠落した一時領域は作らない。原本/軽量版/remoteの再生画面は共通予約により一つだけ開く。長文本文を全文scrollでき、停止・確認・閉じるは固定footerから操作する。全12文字サイズへの対応と実操作/アクセシビリティの検証結果は分ける。

## データ契約

以下は機能上必要な論理型。`UUID`等の例はローカル識別用であり、サーバーの既存ID形式を断定しない。日時はタイムゾーンを含む撮影時点を失わない表現とし、表示用の時刻変換と保存値を分ける。`nil`を成功・失敗・未検証の代用にしない。

S44の補正設定では、保存済み希望がない初回だけ `standard` を設定案の第一候補にする。これはPRDの標準相当候補を具体化した変更可能な希望であり、対応や実適用の保証ではない。保存済み希望を優先し、非対応でもOFF・別モード・別の記録方式へ自動代替しない。既存SDK候補の `off`、`standard`、`cinematic`、`cinematicExtended`、`previewOptimized`、`cinematicExtendedEnhanced` を保持するが、製品のモード数・名称・強さの正式採用はU6の未決事項として残す。

設定画面は現在のカメラ・4K・fps・Logに合うformatから補正候補を絞り、「候補・出力は未確認」「未確認」「非対応」と理由を表示する。format上の候補を、コーデック・記録方式を含む実接続の支持や実適用へ昇格させない。`previewOptimized` はプレビュー用の候補として保持し、現在の4K記録には使用できない理由を示す。条件変更後に候補外となった保存済み希望も表示に残し、本人がOFFまたは対応候補を選べるようにする。

`RecordingIntent`は通常撮影で試験参照を省略でき、探索記録は従来の試験参照を保持する。暦日時はREC受付時に一度だけ観測し、ミリ秒精度へ揃えた同じ値を保存意図と媒体metadataへ渡す。実記録開始や最初のフレームの時刻とは区別し、後続の転送/Photosでもこの撮影日時を保持する。この契約の合意を、実機の媒体metadata・記録品質・G2Bの検証完了と扱わない。

原本本体と管理記録を分け、整理/破棄で本体を削除しても撮影ID・内容対応・本人操作・保存検証・確認・写真登録・削除結果を保持する。通常一覧/破棄履歴は同じ正本から導出し、容量整理成功は通常一覧、同じ破棄操作の実削除成功を照合したものだけ履歴とする。履歴用に原本を移動・改名・隠蔽せず、結果不明を成功履歴へ入れない。

S28で取得したMacの保存原本catalogは、同じjournalの観測から`LibrarySnapshot.remoteItems`へ別投影する。ローカルの撮影保存記録・原本参照・正常保存・自動bind・破棄履歴を生成しない。capture IDのUTF8 bytesと内容世代/hash/byte数で同一性を区別し、同IDの別内容やlocal記録との衝突を要照合として保持する。撮影日時が提供されなければ「撮影日時不明」とし、保存記録あり・現在のMac原本存在は未照合・このiPhoneとの対応なし/要照合・軽量版未取得を分けて表示する。正式保存検証・公開版・確認・写真保存の成功に置き換えない。

### D8 非同期操作と再開条件

全ての長時間操作に、`operationID`、対象ID・内容世代、試行世代、ユーザー意思（開始受理済み/停止済み/キャンセル済み）、状態、待機理由を持たせる。待機理由はWi-Fi不在、REC/録画、保存・異常終了処理、権限、接続先、順番待ち、ユーザー停止を集合で持てる。同時に複数の理由がある場合、一つの解消だけで再開しない。OSが許す既開始upload/downloadの背景・ロック継続を対象とし、OS待機・中断・強制終了・接続不能を区別して復帰時に対象と結果を照合する。

複数操作には本人のまとめて開始する指示を識別するID、操作種別、受理時点の固定した対象集合、動画別の操作ID・対象/版・状態への対応を持たせる。集合の成功値で個別結果を上書きしない。通信の個別失敗はその結果を残し、依存しない動画を続行する。共通問題は影響する処理を待機させる。選択状態は開始意思の証拠にせず、開始受理後にネット実行前で順番待ちの動画は指示済みとして扱う。新しい動画を集合へ自動追加しない。

条件付き自動再開は、本人が開始受理済み・未完了・未停止/未キャンセルである通信について、Wi-Fi・録画/保存・認証/接続・対象/版・既完了処理・操作の寿命等を再確認して行う。本人停止は復帰や再起動で解除せず、キャンセルはその依頼を終える。再実行は新しい本人操作から既存結果と照合する。終了済み再生、未実行の削除、結果不明の「写真」追加の自動再実行は含まない。操作の寿命・期限、通信量/頻度等の未合意値は追加しない。保存/復旧・二重処理防止の実装境界と未接続はarchitecture・現行tasklistへ記録する。

セッション中の解析結果は一時状態、設定・撮影記録・操作意図・保存検証証拠・版/確認/失効・「写真」登録・削除結果は復旧に必要な永続状態とする。表示キャッシュは正本にならない。保存失敗なら「操作受付」と「記録確定」を分け、確認済みや削除完了へ進めない。

## 状態遷移

### S1 撮影・音声と録画優先

```mermaid
stateDiagram-v2
    [*] --> preparing
    preparing --> ready: 必要な記録条件が成立
    preparing --> blocked: 権限・入力・保存先の問題
    ready --> starting: REC受理・通信の再開を閉じる
    starting --> recording: 音声付き記録開始を確認
    starting --> finalizing: 開始失敗・中断
    recording --> finalizing: STOP・確認済み音声障害・記録不能
    finalizing --> preparing: 記録終了・次の準備
    blocked --> preparing: 本人の再試行・設定変更
```

- **RECの条件**: 有効な対応組合せ、カメラ・音声・記録先の準備、現在の記録処理との整合。ND警告・解析中・人物未検出・WBの安定待ちは開始条件に含めない。開始中のREC連打は同じ操作として扱い、二つの原本ライターを起動しない。
- **通信停止**: REC受理時に端末上の動画送受信へ一時停止を発行し、再開条件を閉じる。サーバーの確認応答を待つ設計にはしない。実際に通信を止められない/記録資源を確保できない場合は開始中の理由を表示し、停止要求を出しただけで両立を達成したと扱わない。影響時間とOSの停止動作は実機検証する。
- **再開の内部許可**: REC/保存/復旧のholdと同じ同期境界で、SDK実行直前の許可を一度だけ消費する契約を持つ。holdが始まれば発行済みの古い許可を使わず、begin→end後も再利用しない。発行時の判定だけで通信開始済みにせず、新しい本人承認や操作も要求しない。この契約/配線の追加と、nativeが正のresumeを行わず`notExecuted`を維持すること、全媒体の実停止/実通信中RECが未成立であることを分ける。
- **保存との分離**: 撮影セッションが次の準備へ進んでも、停止したClipRecordはS3のfinalizingを保持できる。保存・異常終了のI/Oが残る間は大きな通信を再開しない。次REC可否は必要資源の準備から判断し、管理表示・サムネイル待ちを加えない。
- **音声**: checkingでは有効確認ができるまで準備中を示す。静寂・小音量・音割れと入力到着/書込障害を分ける。確認済み障害は録画中表示を終えて停止・部分保存を試みる。入力正常でも書込失敗は正常録画として扱わない。
- **復旧**: 保存結果の照合を優先し、本人の「再試行」ごとに音声入力/出力だけを1回再構成する。復旧後はreadyに戻すだけで自動RECしない。無到着2秒・復旧上限5秒をU7の変更可能な暫定製品設定として使い、実機採用・品質はDV-10で確認する。効果不明な全体再起動をしない。
- **中断・復帰**: OS中断・画面ロック・バックグラウンドで録画継続を保証しない。中断時は可能な停止・確定を試み、復帰/再起動はS3の照合後に準備する。中断前がrecordingでも画面上だけ録画中へ復元せず、自動再録画もしない。

通常撮影の音声表示は待機中から実sampleの到着と入力経路を確認し、録画中も音量・入力・到着・書込を別々に示す。静寂のsampleも正常な到着であり、音量上限の表示と確認済み障害の赤い×・理由を区別する。音量を計算できない形式は音量未観測とし、そのことだけで入力障害にしない。Movie方式で観測用sampleが届いても、Movie内の音声書込成功とは扱わず、個別の書込結果が取得不能であることと保存後の検査を示す。

確認済み障害は音量更新や後続sampleだけで消さず、開始抑止または記録停止へつなぐ。停止したクリップの保存結果と、次の撮影に向けた音声復旧の結果を分けて表示する。2026-10-18のS43で、無到着2秒、本人の再試行ごとに音声入力/出力だけ1回再構成、復旧上限5秒を変更可能な暫定製品設定として本人が合意した。通常経路では `ProductCaptureFactory` からNativeとcoordinatorへ同じpolicyを注入し、無到着期限判定と本人再試行を有効にする。復旧中も2秒の無到着判定が働き、5秒は復旧全体の上限である。有限復旧は実入力到着を確認して本人のREC待機へ戻し、自動録画しない。復旧処理が時間切れになっても、処理の終了・資源解放が確認できるまでは次のRECや重複再試行を許可しない。製品接続・実装完了判定・検証証跡は現行tasklistを正本とし、暫定合意を実機採用・品質合格へ昇格しない。実音声・同期・復旧品質はDV-10で扱う。

WBの合わせ直しは、録画中で現在の対応能力が確認済みの場合だけ本人操作を有効にする。WB状態と操作できない理由を表示し、能力が未取得・未確認の場合を対応済みと扱わない。合わせ直し中は重複操作を受け付けず、測定と再固定の完了を確認して状態を更新する。固定の待ち時間で完了を推定せず、ISO・絞り・シャッターは維持する。

### S3 原本保存と起動時の復旧

`recording → finalizing → saved / partial / unknown / failed` を撮影ごとに管理する。起動時には未完了操作の記録とアプリ管理領域の対象ファイルを照合し、結果未確定の項目を通常のsavedへ混ぜない。

| 照合結果 | 更新と表示 | 次の操作 |
| --- | --- | --- |
| 保存完了の証拠と音声・映像を含む対象ファイルが一致し、内容対応も確定 | 正常保存 | 再生・転送・条件に応じた整理/破棄 |
| 保存結果はcommit済みだが内容対応が未確定 | 保存分類を保持し、原本が存在するときは「原本あり・内容の対応未確定・要照合」。未対応だけを削除結果不明と表示しない | 内容対応が確定するまで原本再生・転送・容量整理は不可。次RECはF1の準備条件で判断 |
| 一部だけ読める/正常区間だけ確定 | 部分保存。失われた可能性を表示 | 部分内容を確認して転送/破棄。部分ファイルの救済成功を保証しない |
| 記録とファイルが食い違う、アクセスや検査が未完了 | 結果不明、照合が必要 | 照合を再試行。確定前の転送・容量整理は不可。破棄は対象を確定できた場合だけ別確認で扱う |
| 書込失敗が確定し利用可能な原本なし | 保存失敗 | 理由と再撮影/設定変更等を表示。存在しないファイルの削除成功にしない |

書込終了通知後でも永続記録更新前に中断し得る。復旧は最後の表示値ではなくファイルと操作記録から行う。ライブラリを開いたことが照合開始の唯一の契機にならないよう、未完了操作の復旧はアプリの管理状態に属する。

内容対応の後処理中や失敗後にアプリが終了しても、保存済みの結果と原本ファイルを保持する。再起動後は記録とファイルを読み取り、未対応を要照合のまま表示する。今回のS41修正では自動再bindや新しい再試行UIを追加しない。一覧読込み中の追加更新要求は保持し、後処理の完了が表示へ反映されないままにならないよう再読込みする。

### S4 動画通信・保存検証・変換

- 動画本体の共通ゲートを原本アップロード、軽量版の写真保存用取得、軽量プレビューのストリーミング/一時取得、サムネイル等の全媒体経路に適用する。直接配信・再開・背景でもWi-Fi限定とし、VPNの基礎回線も対象とする。Wi-Fi不在、REC開始/録画、保存・異常終了処理中は送受信を止める。ローカル再生はこのWi-Fiゲートを通さない。

この接続単位は1chunk/attemptとし、次chunkやretryには新しいGET予約/観測と新attempt/sourceを必要とする。起動時再送・旧source採用・自動次chunkを追加しない。local chunkの準備、SDKのchunk終端、自身資源の閉鎖/使用解放、Macのchunk receipt、原本全体の保存検証を分け、chunk完了から原本送信完了・verified・finalize/変換開始へ進めない。strict拒否はattempt/原本使用/copy/SDK生成より前に適用し、nativeの正の送信開始は未成立とする。local技術fixtureと型付き背景接続、全媒体停止・正式producer・実機品質を分け、実行版ごとの検証状況・未実施/失敗を含む記録は現行tasklistと証跡を参照する。

callbackは同processで実作成したtaskのsession/bindingと応答期待値へ照合できる対象だけを固定し、private URL/旧task・再openから媒体を採用しない。同FDの有界read/hash、stop後のworker実join/自身FD閉鎖とSDK実終端を分け、pin失敗時のclose不明を資源なしにしない。後段の最終採用は実ticket/local response観測commit・現UUID/登録/版/epoch・記録由来日時・全hash・成功した実SDK終端/自身閉鎖を要求する設計規則で、現componentからverified記録・ownerClosed commit・lease解放を生成しない。通常full plan・実SDK受信・strict native正resume・正式producer/全媒体・実機品質は未完とし、実行版ごとの検証状況・未実施/失敗を含む記録は現行tasklistと証跡を参照する。

S28は既存登録・既知原本について、本人の「状態を同期」から媒体なしの失効1pageとmanifestを取得し、続きを明示操作で進める経路を同writer・動画別表示へ接続した。既知原本はlocalの論理原本と、同store UUID/現登録のcommit済み保存原本catalogを合わせて開始時に固定し、元UTF8 bytesと内容identityで重複を区別する。未解決失効をcursorと独立に保持し、再openではnullから再照合する。元mutation・旧outboxのexact照合とawait後の登録/store一致を確認し、撮影日時と取得済みの保存・検証・版/失効の事実を分けて示す。同期から媒体開始・新しい明示確認を生成せず、背景履歴/未知ownerの終端を確認できない対象は失効ACKを保留する。既存登録のこの部分接続と、再登録全体・通常媒体操作・全S28/実機受入を区別する。

同じ起動中の担当が所有する既知uploadは、実際に保存された失効予約に対応する停止を状態同期から扱う。停止を扱った最初のpollは未解決に残し、その操作内でACKを出さない。後の本人の明示pollで実通信taskの終端・自身sourceの閉鎖・使用権解放・停止記録と最新の全task/対象journalを照合し、他の媒体使用者も終了した後だけ既存の失効保存/ACKへ進む。閉鎖済み旧upload履歴の観測と、旧未閉鎖sourceの採用/推定解放を分け、未知taskやcopy/開始途中・download等の未解決を保持する。この部分接続を通常送信開始・全媒体停止・実機受入の完了へ拡張しない。

manifest全体の観測は、既存の確認状態に版を採用する処理と分けて同じ管理記録へ保存する。local一覧/詳細とremote一覧は、最後に照合した公開版ID・世代・媒体形式・未公開・置換待ちと、失効・部分/完全取得記録・実媒体未照合を独立表示する。公開版の観測だけで再生可能や確認済みにせず、未取得媒体はオフライン再生不可とする。未公開の観測でも以前の公開/確認記録を消さず、失効済み確認を復活させない。不明commitは元mutationの照合を続け、版採用だけが確定しmanifest観測が未保存の操作は部分結果に残す。実装の部分接続と、自動検証・正式Rec.709媒体・実機受入は現行tasklistで分ける。

保存原本catalogの発見は、この既知原本の状態同期とは別の本人操作とする。現登録のBearer/secretで同destinationの旧completed bindingと有効な保存evidenceに対応する原本identityを取得し、Connectionの「Macの保存記録を照合」から1操作1ページ・明示続行で進める。元request cursor・現登録/store UUID・command/pageを同writerへ観測として加算し、commit不明では元mutationのexact lookupが確定するまで続きを取得しない。空/重複ページで過去の記録を消さず、再open後は保持した観測を表示し、先頭から再照合する。結果後に同じLibraryを更新するが、動画取得・新確認・旧ACKの代用を生成しない。有界wire/SDK契約はarchitecture、実行版・必要検証の結果は現行tasklistを参照する。

### S5 明示確認・失効と版の差し替え

端末上の確認記録の確定を容量整理に使用する。サーバーへの確認同期が未完了でも、原本・公開版の証拠と端末の有効な確認が全て揃えば、同期通信そのものを容量整理の追加条件にしない。サーバーは確認通知の有無に頼って差し替え可否を判断せず、対象端末が保持し得る旧版の確認を失効させる契約を持つ。

1. V1を1本ずつ再生する際に原本/変換版/映像/世代を固定し、実再生到達を確かめたうえで本人の確認イベントを受けた時点に最新世代と再照合する。ストリーミングを第一候補とし、通信中断・再開でも対応を維持する。全体取得や全編再生を確認条件にせず、再生到達を原本全内容検証にしない。`pending`の永続化から`valid`の確定までを区別し、中断や書込失敗は未確認/確認不明とする。複数選択で未確認の動画を確認済みにしない。
2. Mac miniでV2を生成しても公開V1は維持する。V2生成の成功だけではV1確認に影響を与えない。V2生成失敗でも未失効V1の有効性は保つ。
3. 差し替え要求ではサーバーが旧原本/映像/世代と旧版を配布した対象登録を指定し、確認同期が未到達でも必要ACKを登録別に固定する。端末はS6と共通の項目単位の排他境界で失効を永続保存し、保存成功後にだけ、その登録・失効ID/原本/映像/世代に対応する応答を返す。
4. サーバーが全ての必要な永続保存の応答を確認してからV2への差し替えを確定する。応答の欠落・不明・端末オフラインならV1を維持し差し替えを保留する。タイムアウトや推定、古い/別登録の応答を代用せず、旧登録の必要ACKを新登録のACKで置き換えない。
5. 失効保存後は応答消失、切断、再起動、V2の保留/生成失敗でも旧確認を復活させない。失効済みV1を再ダウンロード/再生しても、新映像の明示確認の代わりにしない。新版が使えない間は容量整理不可と理由を表示する。
6. V2公開の証拠を取得し、その同じ映像を再生・明示確認して新世代の確認を確定したら容量整理を再判定する。同じV1の単純な再取得やWi-Fi切断だけでは手順3の失効を起こさない。

完全取得済みlocal枝では、実AVPlayerの進行で得た同一版/tokenに対する、開いている単数再生画面の「この軽量版を確認」だけが確認操作になる。停止/自然終了後も同画面のtokenで操作できるが、閉じる/再起動でtokenを消去し、自動再生や自動確認はしない。確認保存が不明なら同token/actionの記録を照合し、新しい操作へ置き換えない。画面の停止/閉鎖は実読取終端とその再生の使用権だけを解放し、最後のuseの回収は既存規則に従う。未知の他useや過去の写真結果は保持する。このlocal消費側の配線を正式媒体の生成・通常取得/streaming、全S28や品質受入の完了へ拡張しない。

再登録で旧登録の必要ACKを省略しない。応答不能の旧登録から必要ACKを得られない該当動画の差し替えは、初期版では無期限保留とする。保留中も利用可能な既存公開版と、新登録の通常の一覧・取得・再生、別動画の独立した転送・検証・変換を扱う。旧確認を新登録へ自動復元せず、新登録で容量整理する対象だけ、その版を再生・明示再確認する。全履歴の再確認や、一律の原本再転送・軽量版再生成・写真再保存を通常利用の条件にしない。通常再起動と再登録を区別し、多端末サービスを新たに必須化しない。具体的な登録・配布・失効の永続表現と冪等照合はI3で扱う。この確定契約と、S28の再登録全体・通常媒体UI等の未接続・DV-15の実機未受入を分ける。

S28は登録意図・登録記録が空の現在storeと、別store UUIDへ結び付いた有効なv2接続情報を区別し、本人が別操作で新しい登録を始める部分を接続した。通常の再照合・登録・保存済み情報による続行・初回入力では以前のstoreの資格情報を採用しない。同storeで中断した処理は保存済み情報を照合して既存の続行経路を使う。現在storeのconnectionがなくても同UUIDにinitialが残る場合は、別destinationの入力で回避せず新登録を保留する。破損・読取不能・v1 unbound・対応不明を新登録の許可として扱わない。

画面は以前の登録情報を保持することと、以前の確認・失効ACKを引き継がないことを説明し、接続先/認証情報の別入力と明示開始を求める。同じMac miniの既存bootstrap情報を本人が再入力することもでき、別Macや新しいtoken発行を条件にしない。開始処理は現在store UUIDの永続確定後に接続先を検査し、そのUUIDに束縛した別の接続情報・intentだけを作る。処理途中も同UUIDと登録空を再照合し、旧記録やsecretを移行・上書き・削除しない。キャンセル/離脱や再照合で新登録入力を閉じる場合はbearer入力を消す。新登録開始と保存原本catalogの部分接続は分けて必要検証を現行tasklistで追跡する。catalog取得だけで正式保存検証/公開版を照合済みにせず、manifest観測と通常軽量版再生・確認・全媒体操作を分ける。新namespace資格情報の実SDK受渡しで得た隔離loopbackの部分証拠と、通常HTTPSの正の結合・専用UI等の必要検証については現行tasklistで範囲/実行版/結果を分け、全S28と実機DV-15の未完了を保持する。

### S6 容量整理・破棄の排他と結果確定

二つの目的は同じローカル削除I/Oを利用できるが、許可規則・イベント・記録は分ける。容量整理は本人がまとめて実行指示した対象集合を固定し、動画ごとに以下の排他・結果確定を適用する。破棄は1本ずつ対象・消失リスクを確認し、一括破棄へ拡張しない。削除対象はアプリ管理領域内で確定したLocalOriginalRefに限定し、Mac mini削除APIや「写真」削除APIを呼び出す契約を持たせない。

| 競合 | 機能上の扱い |
| --- | --- |
| 対象を録画中/保存中 | 両操作を保留し、録画停止・保存結果の確定後に対象を再提示する。確認画面だけで将来の自動削除を予約しない |
| 他のクリップを録画/保存中 | 新たな削除I/Oは待機させる案U1。実行済み削除の短い確定区間は安全に終え、RECを不要に待たせないよう測定する。後で無確認実行する予約にはしない |
| 対象を転送中 | ローカル読取を止めて解放・整合を確認してから削除する。破棄では「転送を止めて破棄へ進む」を本人が選ぶ案U1。停止要求受付だけで削除せず、待機後に対象/リスクを再提示する |
| 対象をローカル再生中 | 再生を閉じ読取を解放してから実行。別版の写真保存・Mac mini変換はローカル原本を参照しないと確認できれば、原本削除の条件に追加しない |
| RECと既に確定区間へ入った削除 | 新たな破壊的処理を増やさず、処理中対象の照合に必要な最小処理だけ完了/記録する。録画開始への影響はT18で測定し、削除を途中放棄して成功表示しない |
| 同一対象への連打/容量整理と破棄の同時操作 | 操作IDと項目排他で一つだけ受理。もう一方は進行状況を表示。目的を途中で付け替えない |
| 確認失効と容量整理 | 同じ端末・原本に対する一つの順序へ直列化。失効永続化が先なら再判定で容量整理を拒否。削除実行の確定区間が先ならその結果照合まで失効応答を待たせ、サーバーはV1を維持する |

削除実行の確定区間は「対象同一性と最新条件の再判定→本人操作に対応するRemovalIntentの永続保存→実ファイル削除→ファイル/管理記録の照合」とする。複数の容量整理でも各実行直前に保存・全内容検証・明示確認・対応・失効状態を再照合し、この区間と確認失効の永続化を同じ項目排他で保護する。選択時の一括判定や候補表示を実行許可にせず、不成立の動画は削除せず破棄へ移行しない。動画別の成否・未処理・要確認を保持し、整理の処理順・中断操作等の具体方式はU1の残件とする。ローカル削除のためにサーバー排他や再接続を要求しない。失効が後から処理された場合でも確認状態は失効へ進み、過去の正当に完了した容量整理という事実とは分ける。

停止・アクセス失敗などで確定区間を終えられないときは結果不明を永続保存する。再起動時はネット接続より先にローカル照合を行い、以下で復旧する。

| ファイルと記録の照合 | 結果 | 再実行 |
| --- | --- | --- |
| 対象の削除意図があり、正しい場所・同一対象の消失を確認でき、管理記録も更新できた | 削除済み（容量整理/破棄を明示） | 同じ操作を繰り返さない |
| 同一対象が残存し、削除未実行または失敗を確定 | 未削除 | 新しい本人操作で再判定。容量整理はその時点の失効を含め確認 |
| 場所/同一性が不明、参照不可、記録更新失敗、処理との対応不明 | 確認が必要 | 自動で再削除しない。照合再試行と理由を表示 |

アプリ再起動や通信の自動再開を契機に、未実行の破壊的操作を自動実行しない。中断した複数容量整理は動画別に照合し、未実行/未削除の対象は新しい本人操作から再判定する。転送を止めた後に破棄を取り消した場合も、ユーザーが停止した転送を勝手に再開しない。サーバーが既に受信した原本や生成済み軽量版は破棄操作の範囲外として維持し、状態照会で判明した事実を表示する。

結果commitにも同じwriter内で対象ファイルの最終照合を行い、古い存在観測で新しい削除結果を上書きしない。容量整理成功は通常一覧に残し、実ファイル不在と同じ破棄目的・操作の成功記録を照合したものだけ履歴へ分類する。不明・未削除・未処理は通常導線に残す。履歴は管理記録で、原本を残すゴミ箱ではない。S32/S33はこの実削除・観測だけの復旧を実装・自動検証済み。S34の通常単数破棄に加え、条件付きの通常複数容量整理を同じCompositionへ接続した。接続と必要検証の実行版・結果は[現行tasklist](../.steering/20260929-device-independent-implementation/tasklist.md)で追跡し、新規Photos/複数保存、正式証拠producer、実機DV-17とS34全体の完了を別判定とする。

複数整理では全選択原本の存在・内容/保存記録の対応を確認し、適格候補が1件以上あれば固定集合の確認画面を開く。動画別の撮影日時・サイズ・最後の有効な保存検証と整理条件を示し、本人の確定後も各削除直前に再照合する。条件不足や通信終了不明の動画を含む集合でも、その動画は未実行/要照合として残し、独立して条件を満たす動画を処理する。一部成功を全件成功と表示せず、未解決子の受付閉鎖を維持しながら、終了を確認できた別の子だけを再観測して受付を開く。オフラインの操作は最後に取得した証拠に基づくもので、Mac mini原本の現在の存在を確認した表示にはしない。

S34-BG01は対象に記録された全historical uploadについて、SDK実終端→自身のsource FD閉鎖→ownerClosed commit→exact lease解放→stoppedを照合できた場合の単数破棄を加算した。全task receipt集合とhash前の対象一覧をunlink直前の同writerで再構築・照合し、通常modelの本人による対象/消失リスク確認→実MOV unlink→再open/履歴へ接続する。この照合は条件付き複数整理にも適用し、保存検証・有効確認・支持schemaは容量整理固有の条件として最終writerで再判定する。unknown・copy中・attach gap・旧source・task再利用/同operation複数attempt・download・活動中を保守的に拒否し、未知の自動復旧や活動中taskの自動停止を成功扱いしない。原本削除後もupload copyと管理記録を保持し、回収policyを追加しない。旧実SDK試験のFD閉鎖はManagedUploadSource自身の保持FDに限り、strict permitとMac側notExecutedは注入である。その証拠だけで後続の複数整理の必要検証、SDK所有全FD・通常の厳格な通信・正式Rec.709証拠producer・Photos/複数保存の成立へ昇格しない。合成証拠やSDK fakeを使う技術試験も、実転送・標準変換・品質や実機受入の証明としない。

### S7 「写真」登録・重複防止・一時コピー

動画別に `未指示 → 開始意図保存（順番待ちを含む） → 取得 → 登録意図保存 → 登録中 → 登録成功記録 / 追加未実行 / 失敗確定 / 照合が必要` とする。新規の開始意図はWi-Fi接続時だけ受理・保存し、複数選択時は対象集合と動画別の操作/版を固定する。切断後は既開始処理の取得を待機させ、順番待ちを含めS4の条件再確認後に通信を自動再開する。動画別の取得・登録の成否と未処理を表示する。取得済みの版を使う登録以降のローカル処理には、Wi-Fiの継続を要求しない。同じ撮影・変換版の操作を直列化し、ボタンの無効化だけに重複防止を依存しない。結果不明の登録は照合を優先し、通信再開によって再追加しない。

完全取得済みlocal軽量版の単数/複数写真保存は、local項目とremote保存原本行にまたがる写真用の選択集合を、本人の開始時に固定する。同じ管理記録へ親操作・子operation・対象媒体/版/日時を保存し、動画別に順番待ち、登録開始、未処理と既存のPhotos結果を表示する。写真側の存在照合と追加結果は分け、必要な対象だけ理由付きで照合へ進む。remote行のために原本削除用の参照を作らず、写真保存を原本の現在存在や軽量版の明示確認の条件に結び付けない。

初回受付はnativeの現在Wi-Fi観測がある場合だけとし、不明・不適合時は受付/媒体使用/Photos追加を始めない。受理済みの完全local処理にWi-Fi継続は要求せず、画面移動後もアプリ内の同jobが集合を保持する。REC/保存等では未開始子を待機させ、条件解消後に現在状態を再照合する。再起動後の順番待ちは本人の明示続行/取消だけを扱い、開始済み・登録意図のみ・結果不明の子を自動再追加しない。不明commitは同じ操作を照合し、結果不明を新しいSDK追加へ置き換えない。正式媒体の通常取得からの保存、全producer・実機Photos/品質の成立とは分け、必要検証の結果は現行tasklistで追跡する。

同じ起動中の担当がPhotos非開始を確定できる意図は、本人の要求照合/続行から保存結果と使用終了を照合する。Photos追加を呼び直さず、元の追加結果不明を成功へ変えない。再起動後にその非開始事実を推定せず、古いunknownの再追加・使用権解放へ広げない。capture待機の通知は実行中の子処理へ合流し、完了した履歴を自動処理へ戻さない。

最終のPhotos追加直前にも、同じwriterの現在の意図/登録/版・失効/未解決削除予約、完全な一時媒体と使用権、撮影待機、同依頼の共有開始権を順に照合する。権限確認や非同期handoff後に撮影待機が入った場合は、同じlive意図・媒体使用・FD・処理を保持して待機し、未実行結果や追加失敗として確定しない。通知後は現在条件を取り直し、別意図や新しい媒体使用を作らずに再判定する。有効な取得済み軽量版には、物理原本の存在やlocal原本bindingを追加条件にしない。

本人の取消は同じ固定集合のlive子に対応付け、Photos未受理と確定できる場合だけ非開始の結果/終端保存と使用解放へ進む。Photos受理後は即時取消を保証せず、実completionと保持媒体の終了を待つ。二つの担当が同じ依頼を扱っても重複追加や別ownerの使用解放を許さず、再起動後の既存意図・結果不明は自動追加しない。実行版ごとの検証状況・未実施/失敗を含む記録は現行tasklistと証跡を参照する。全媒体停止・通常strict通信・正式媒体生成・実機Photos品質の未完了を保持する。

REC受付後は既知Photosの開始前処理を取消/wakeして終端待ちへ進め、受理済みの追加は実completion・自身FD閉鎖・終端/使用解放の記録を照合してから撮影する。写真保存batch全体の本人取消へ置き換えず、外部の保存結果不明と端末内の処理終了不明を分ける。保存結果がunknownでも端末内の実終端/解放を証明できればRECへ進み、その証拠が不明なら待機する。待機中のSTOP/leaveはそのRECだけを取り消し、内部の実終端待ちは保持して、古い応答で別RECを開始/解除しない。Photosがない新規/撮影専用rootは、同じ最新記録とowner/世代から使用者不在を確認できれば登録やUUID生成なしで撮影を続ける。実行版ごとの検証状況・未実施/失敗を含む記録は現行tasklistと証跡を参照する。写真保存成功や全媒体停止へ昇格しない。

- 登録成功は「写真」の結果と対応情報の永続保存で確定する。ダウンロード完了でsavedにしない。アプリ記録前の中断でも登録意図と操作IDを保持し、結果照合を優先する。`BackendOutcome.succeeded(record)`は操作記録の確定を表し、記録内のunknown/failed/notAttemptedを写真保存成功へ変えない。使用権解放の成功も追加結果とは分ける。
- DI-06に従い、通常は本人の保存操作に必要なときだけ追加権限（add-only）を求める。結果不明等の照合が必要なときだけ対象と理由を示し、本人の照合操作で読み取り権限（readWrite）を案内する。起動・一覧の再読込みでは要求せず、権限不足で撮影を止めない。
- 照合は保存済みの写真側識別情報だけを使い、名前・日時による探索で対応を推測しない。識別情報の欠落・拒否・限定アクセス・読取許可済みでも未発見なら未保存と断定せず、要確認を維持する。管理記録の欠落だけで再登録せず、重複回避のために既存写真を削除する処理も持たない。
- 過去の追加結果と「写真」の現在存在を別に保存・表示する。存在が確認できても過去の不明結果を成功へ書き換えない。成功・不明・登録意図だけの中断は再追加を許可しない。「写真」の処理が未開始、または未追加が確定した失敗だけ、新しい本人操作を直前の操作に結び付ける明示再試行を許す。同じ媒体・版・撮影日時を照合し、新しいphoto使用権を獲得して新意図へ束縛する。旧useは再利用しない。後から本人が写真側で消した動画の手動再保存はU2の未合意事項として残す。自動再保存はしない。
- 登録結果とSDK終端は別に記録する。SDK非開始の確定、または実完了とFD閉鎖を元の意図・使用権・owner/epoch・ファイル同一性へ束縛して保存し、exact commit確認後にその使用権だけを解放する。結果不明でも新終端証拠に基づく解放は可能だが、追加結果やidentifier・再追加抑止を消さない。復元とowner閉鎖もこの証拠で失効時の全reader解放へ接続し、稼働中SDK・Task取消しだけ・finish失敗・別intent応答や証拠のない旧unknown/意図のみからは解放しない。従来の成功recordに基づく限定回収は維持する。
- 同じ登録・結果列・終端証拠・回収方式に対する同時の回収は、一つの処理へ合流させる。scope閉鎖全体を相互待機させず、異なる証拠や方式、別owner/useへ解放許可を広げない。
- 失効処理が先に元useを解放しrootの実FD閉鎖まで終えた後にcallerの同じ解放要求が到着しても、元intent/terminal/releaseのmutation・commit、同use・directory/file・store identity・使用中でないことと、自ownerの実終端を読取照合して扱う。新FDやrootの再open・回収・unlink・再追加は行わず、部分閉鎖不明や証拠不足はunknownとする。照合できた応答でも元の追加結果・identifier・再追加抑止とコピー保持を変えない。
- ストリーミングのバッファ等の一時データと登録用ファイルは用途・使用量・所有者を管理し、空き容量不要とは扱わない。再生専用データは使用終了後に、登録用コピー本体は登録成功かつ全使用者なしで回収し、アプリ再生用の恒久コピーへ転用しない。終端により使用権を解放してもunknown/failed/notAttemptedのコピーと照合記録は保持する。確認記録は一時データ回収後も維持する。確認のために登録用の全体ダウンロードを必須にしない。
- 取得失敗・中断の断片は次回起動等で照合し、再開対象でないものを回収する。動画別と全体の一時使用量を管理し、容量不足では新規取得を止め、所有者のあるデータを無断で消さない。未解決結果の照合記録は残し、再取得可能な本体を解放できる設計にする。保持期限・容量上限・バッファの方式はU2で合意/評価するため、無期限・無制限保持を既定にしない。

S31の実装は、実Photos追加・同じ管理記録への意図/結果/終端証拠保存・完全取得済み媒体の受渡しと、既存登録の理由付き照合・結果表示を含む。完全local媒体を使う単数/固定複数保存consumerを加え、正式Rec.709軽量版の生成・未取得媒体からの通常取得producerの未接続と分ける。local/remote混在選択・batch/子状態と既存Photos結果の接続、必要検証の成否をそれぞれ追跡し、検証前に保存成功や全体受入へ昇格しない。結果不明・失敗コピーの自動回収方針も残件とし、未合意の期限・容量policyを追加しない。実装と検証結果は分け、結果の正本は現行tasklistとする。初回OS許諾画面・限定アクセス選択・本人の写真側削除後・実写真の映像/日時/音声/品質は未確認としてDV-16へ残す。

### 共通の非同期処理規則

- 完了イベントは操作ID・対象ID・対象内容世代・試行世代を照合する。再試行前の結果を現在の結果へ上書きしない。必要な外部の確定結果は対応操作の証拠として保持し、表示だけ棄却して状態を失わない。
- キャンセル要求と外部処理の停止完了は別。端末で停止してもMac mini保存や「写真」登録が完了している場合があるため、取り消したことだけで未実行へ戻さない。
- 再生・解析の画面寿命と、保存・確認・写真登録・削除の永続操作寿命を分ける。画面離脱で操作証拠を捨てない。起動時には未完了操作を照合し、破壊的処理や不明な写真追加を自動再実行しない。
- 端末内の時刻比較だけを版の新旧判定に使わず、版/世代/操作IDによる順序を持つ。実装方式はarchitectureで決める。

### 既存実装確認待ちとarchitectureへの引継ぎ

- MediaVault/RN: 隔離snapshotで登録・受信保存・全内容検証・候補job/公開等の技術証拠を得た範囲と、通常通信・正式proof・標準変換・製品UI等の未接続、稼働版/実データの未確認を区別する。旧状態移行やPRD参照コミット以後の必要差分も確認する。配信成立性に大きな制約があれば一時取得を比較し、大規模配信基盤を承認済みにしない。旧試験データの整理対象と操作は別の明示合意を得る。
- 永続化: 同じwriterによるdisk commit/再open、確認/失効・削除意図/結果・写真登録意図/結果、項目排他・観測だけの復旧には技術証拠がある。実採用方式とschemaはarchitecture・現行tasklistを参照し、端末保護/OS実終了、再インストール時の端末識別、残る所有引継ぎ・破損/互換性を別に確認する。
- 撮影/通信: 通常撮影制御とS49のREC/保存待機、S23の背景task/資源、S28の既存登録の明示ページ同期とS34-BG01の終端照合済みupload後の単数破棄を部分接続として保持する。単回同期許可の契約/配線を追加し、正の実SDK resume時の同期hold排他・全媒体の実停止/再開・download受入口・旧source採用・再登録全体/通常媒体操作等は残件とする。OS許可範囲の背景/ロック方針は確定済みで、実成立と未合意の期限/容量policy等を分ける。外部依存・外部ツールは必要性と導入範囲を別途合意する。
- 評価/計画: DIの実装4段階と直接依存ごとの局所保留を適用し、独立作業を実機待ちで一括停止しない。方式の実機採用・品質・PRD受入は別判定とする。数値閾値・試験環境・対象ファイル・破壊的試験の許可範囲は実施前に具体化する。
