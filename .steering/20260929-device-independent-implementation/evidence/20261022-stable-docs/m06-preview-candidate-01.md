## ドメイン用語

### FrameRelay・本人

- 定義・使用: FrameRelayは家族・旅行動画の撮影と媒体管理を行う個人用ネイティブiOSアプリ。「本人」は撮影・転送・確認・削除を判断する利用者。要求上のiPhone 18 Pro・Mac miniという端末名は、能力の検証済みを意味しない。
- 参照先: [PRD「プロダクト概要」「ユーザーと課題」](product-requirements.md#プロダクト概要)。

### 原本

- 定義: FrameRelayで撮影し、表示変換や予告を焼き込まず保持するProRes＋Apple Logの音声付き動画。
- 使用・関係: 「iPhone原本／ローカル原本」はアプリ管理領域内、「Mac mini原本」は転送後に改変せず保持する媒体。保存途中・部分保存は保存結果を併記し、原本同一性で対応させる。
- 参照先: [PRD FR-01・FR-11・FR-14](product-requirements.md)、[アーキテクチャ「保存場所とライフサイクル」](architecture.md#保存場所とライフサイクル)。

### 原本本体・管理記録・通常一覧・破棄成功履歴

| 用語 | 定義・使い分け |
| --- | --- |
| 原本本体 | 音声・映像を含むファイル実体。削除の対象となり、管理記録とは別に存在を照合する |
| 管理記録 | 撮影・保存/検証・版・確認/失効・Photos・削除意図/結果等の対応を保持する記録。原本本体を削除しても保持する |
| 通常一覧 | 撮影項目を独立した状態軸とともに表示する導線。整理成功後も原本なし・軽量版取得/再生可否・確認・Photosを示し、不明/未処理/未削除も要照合等を付けて残す |
| 破棄成功履歴 | 同じ原本・目的・操作について実不在と破棄成功結果を照合できた管理記録の分類。原本本体を移すゴミ箱ではなく、容量整理成功や不明結果を分類しない |

参照先: [機能設計 D6・S6](functional-design.md)、[アーキテクチャ「commitと復旧の契約」](architecture.md#commitと復旧の契約)。

### 撮影プレビュー

- 定義・使用: 撮影待機中・録画中の現在映像。固定標準Rec.709表示の要求があり、Log原本には焼き込まない。構図予告・保存後の軽量版と区別し、閲覧を明示確認へ流用しない。
- 参照先: [PRD FR-02](product-requirements.md)。

### 構図予告

- 定義・使用: 目標倍率での撮影範囲の目安。予告だけでは実倍率を変えず、原本へ焼き込まない。目標選択→予告→本人の明示開始→目標/途中停止とし、ズーム停止とREC停止を分ける。別カメラの画質等の完全再現ではなく、補正の画角変化にも関係する。図示の可逆実装と、速度/許容差・実画角/品質の実機採用を分ける。
- 参照先: [PRD FR-07](product-requirements.md)、[機能設計 D2・U4](functional-design.md)。

### Rec.709軽量版／軽量プレビュー

- 定義: Mac miniで保存検証済み原本から標準Rec.709変換して作る鑑賞用動画。「軽量版」は成果物、「軽量プレビュー」は同じ成果物の内容確認用途を指す。
- 使用・関係: 明示確認と「写真」保存に利用。元fps・向き・縦横比・構図・音声・撮影日時を保持する。1080p・HEVC等はU8の候補で、compress-onlyとは区別する。
- 確認再生: 全体の一時取得を待たないストリーミング（streaming）を第一候補とする。「写真」保存用と同じMac mini生成軽量版の原本・変換版・映像IDと配信内容の対応を再生・通信再開時も固定し、Wi-Fi・REC・明示確認・失効の規則を維持する。固定版実再生等の技術証拠と、正式変換資材・全媒体接続・実機品質を分け、大きな制約があれば一時取得との比較・代案を示す。
- 参照先: [PRD FR-12・FR-13・FR-15](product-requirements.md)、[アーキテクチャ「Mac miniとの必要契約」](architecture.md#mac-miniとの必要契約)。

### 撮影意図・露出評価対象・主役

| 用語 | 定義と本プロジェクトでの使用 | 関係・区別 |
| --- | --- | --- |
| 撮影意図 | 人物・背景のどこを重視するかを示す選択。基本区分は「人物のみ／人物＋背景／景色優先」 | 初回は本人が選択して保存・復元する。未選択もRECを妨げない。人物＋背景を全域同時合焦の保証にしない |
| 露出評価対象 | ND・露出案内で重視する人物等。人物は複数選択を扱う | ピントの主役と別に管理する |
| 主役 | ピントを合わせ、前後移動に追従する対象として本人が指定する一人 | 恒久的な人物識別台帳を意味しない |
| 主役追跡 | 指定した人物への合焦と移動への追従 | 見失い後は変更可能な暫定3秒の猶予中に同じ人物と確かめられた場合に復帰。以後はピント保持・再指定待ちとし、別人へ自動移行しない |
| 追跡OFF | 特定主役への追従を使わず、人物優先AFを使う方針 | ピント固定とは異なる。人物なし時はタップした位置へAFする |

参照先: [PRD FR-05](product-requirements.md)、[機能設計 D2・S2・U5](functional-design.md)。

### ND案内

- 定義・使用: 撮影意図と現在条件をもとに物理ND調整の方向・理由を示す補助。濃く・薄く・許容・両立困難・判定中／根拠不足を区別する。調整は本人が行い、精密段数を保証しない。保留や警告だけでRECを禁止しない。
- 参照先: [PRD FR-06](product-requirements.md)、[機能設計 S2](functional-design.md#s2-撮影制御解析ズームの独立状態)。

### 手ブレ補正・停止候補・レンズ切替

| 用語 | 定義と本プロジェクトでの使用 | 関係・未決 |
| --- | --- | --- |
| 手ブレ補正 | 撮影時の揺れを抑える機能。OFFと程度・特性の異なる複数モードを選ぶ要求 | カメラ・形式等の組合せごとに対応を確認。モード名・数・強さはU6で未決。画角変化は予告・停止支援にも関係する |
| 停止候補 | ズーム時に引き伸ばしを避けて止めやすくするため、撮影条件と画質の根拠を持たせる位置 | 根拠付き近傍候補の本人選択は可逆実装、自動吸着なし。整数倍率だけで高画質とせず、速度/許容差・実機品質はU4。「引き伸ばしなし」は完全無劣化の保証ではない |
| レンズ切替 | 撮影に用いるカメラを切り替える操作 | 移行時の限定ISO補正とその後の値維持を扱う要求で、常時Auto ISOではない。S47の基準/上限等の案は本人未回答で、通常policy=nilを保持する |
| Lens Match | 対応を確認できた場合に共通絞りへ合わせる補助操作の候補 | 未採用の調査候補。可変絞りの対応や特定F値を確定しない |

参照先: [PRD FR-03・FR-07・FR-08](product-requirements.md)、[機能設計 U4・U6](functional-design.md#ユーザー判断待ちの具体案)。

### 明示確認

- 定義: 本人がRec.709軽量プレビューの内容を1本ずつ再生で見て明示操作し、同一原本・変換版・映像への確認記録が端末で永続確定した状態。
- 使用・関係: 途中再生でよく、全体取得・全編再生・一定秒数は要求しない。表示・再生・操作受付や複数選択だけでは成立しない。実再生到達は原本全内容の保存検証や「写真」保存とは別。容量整理の根拠となり、破棄の対象・消失リスク確認とも分ける。
- 参照先: [PRD FR-13](product-requirements.md)、[機能設計 D5・S5](functional-design.md)。

### 容量整理

- 定義: 残す動画の同一原本について、Mac mini保存・全内容検証と同一軽量映像への有効な明示確認を根拠に、本人がiPhone原本だけを手動削除する操作（FR-14）。
- 使用・関係: 最後の有効記録でオフライン実行できるが、現在のMac原本存在は再保証しない。再接続・再視聴・「写真」保存・追加バックアップ・高品質版を条件に加えない。不要動画の破棄と別の規則。
- 複数実行: 条件を満たす動画を複数選択してまとめて実行できる。各削除直前に最新の対象・保存検証・明示確認・確認失効・世代と使用権・排他を照合し、動画別に成否・未処理を保持する。他の動画の成功や集合の成功を削除許可へ流用しない。
- 参照先: [PRD FR-14](product-requirements.md)、[機能設計 D5・S6](functional-design.md)。

### 削除候補

- 定義・使用: 容量整理の証拠条件がそろった導出状態（論理名`CleanupEligibility`）。本人操作・直前再判定・排他は別に必要で、予約・完了やFR-17の許可を意味しない。既存MediaVaultの同名フラグとは区別する。
- 参照先: [PRD FR-14](product-requirements.md)、[機能設計 D5](functional-design.md#d5-明示確認と容量整理の判定)。

### 不要動画の破棄・破棄対象と消失リスクの確認

- 定義: 本人が不要と判断したiPhone原本を1本ずつ削除する操作（FR-17）。「破棄対象と消失リスクの確認」は、対象と保存検証状況を見て、原本を失う可能性を本人が確認すること。一括破棄へ拡張しない。
- 使用・関係: 転送・保存検証・軽量版明示確認前でも可能。Mac mini・「写真」は連動削除せず、検証済み・明示確認済みも作らない。容量整理不可から自動切替しない。待機中の対象・リスク変化は再提示する。
- 参照先: [PRD FR-17・補足R2・R3](product-requirements.md)、[機能設計 F5・S6](functional-design.md)。

### 「写真」への保存

- 定義・使用: 本人が複数選択してまとめて開始でき、Mac mini生成のRec.709軽量版を「写真」へ追加して動画別の結果と対応記録を確定する操作。確認再生と同じ成果物を使うが、取得完了・再生・明示確認とは別の操作・状態。新規開始はWi-Fi時だが、取得後のローカル登録にはWi-Fi継続を要求しない。容量整理との順序は自由。
- 参照先: [PRD FR-15](product-requirements.md)、[機能設計 F4・S7](functional-design.md)。

### MediaVault・compress-only

- 定義・使用: MediaVaultは継続利用・拡張する既存バックエンド。`compress-only`は参照時点のApple Log未変換圧縮プレビューで、Rec.709軽量版と区別する。根拠は2026-09-24の限定スナップショットと、同じHEADに対する2026-09-26の限定ソース確認。
- 確認範囲: 上記の限定ソース確認はRange配信・認証・版IDに限られ、当時はRec.709変換・実再生版への確認・端末失効契約に不足があった。後続の隔離実装/実HTTP・固定版実再生の証拠とは版を分ける。正式資材/品質proof・通常全媒体接続・実回線/実機の成立は別に確認し、大規模配信基盤の採用を意味しない。
- 参照先: [PRD「既存MediaVaultについての限定された根拠」](product-requirements.md#既存mediavaultについての限定された根拠)、[アーキテクチャ「Mac miniとの必要契約」](architecture.md#mac-miniとの必要契約)。

## UI・状態用語

### 操作の粒度・複数選択

| 操作 | R3で確定した初期版の粒度 |
| --- | --- |
| 原本転送／軽量版の「写真」保存／条件を満たす原本の容量整理 | 複数選択してまとめて開始・実行。内部は順次処理でよく、複数同時通信は必須ではない。動画別の成否・未処理を表示 |
| 軽量プレビュー再生・明示確認／不要動画の破棄 | 1本ずつ。複数選択を一括確認や一括破棄へ用いない |

### REC・STOPと撮影状態

- 定義: RECは本人の録画開始指示、STOPは録画停止指示。指示受付と実記録開始・終了は別の時点。
- 開始・遷移: 準備中から必要なカメラ・音声・記録先等が整うと待機可能となり、REC受理後の開始中を経て、音声付き記録の開始確認で録画中になる。STOPや確認済み障害で停止・保存処理へ進む。
- 本プロジェクトでの使用: 人物・ND解析完了やWB安定を待つことをREC条件に加えない。停止後は原本保存結果を別に判定し、音声復旧やアプリ再起動から自動RECしない。
- 関連する論理状態: S1の`preparing / ready / starting / recording / finalizing / blocked`。原本保存結果の`finalizing`とは所有する状態が異なる。
- 参照先: [機能設計 S1](functional-design.md#s1-撮影音声と録画優先)、[PRD FR-04・FR-09・FR-16](product-requirements.md)。

### 希望値・能力照会・実適用値・実機評価済み条件

| 用語 | 定義・使い分け | 更新・成立の根拠 |
| --- | --- | --- |
| 希望値／希望設定 | 本人が選び保存する撮影条件 | 設定入力。端末への適用成功とは別 |
| 能力照会 | APIから端末・カメラ・形式等の対応情報を取得すること | 組合せごとの情報。列挙できただけで撮影品質まで成立したとしない |
| 実適用値 | 撮影経路で実際に使っていることを確認した値 | 端末からの適用結果・観測。UI選択値を代入しない |
| 実機評価済み条件 | 対象の組合せを実ファイル・操作で評価した条件 | 環境と結果の証跡。「評価済み」だけでは合格を意味しない |
| 未確認／非対応 | 成立の証拠がまだない状態／対応しないことが分かった状態 | どちらも無断の代替適用や対応済み表示にしない |

関連する論理名はD1の`CapturePreference / CaptureCombination / CapabilityStatus / AppliedCapture`。参照先: [機能設計 D1](functional-design.md#d1-撮影希望値対応情報実適用値)、[開発ガイドライン「Swift / SwiftUI」](development-guidelines.md#swift--swiftui)。

### WB固定・合わせ直し

- 定義: WB固定はREC時点のホワイトバランスをクリップ内で維持すること。合わせ直しは録画中に本人の操作でWBを更新し、再び固定すること。
- 開始・終了: 起動・待機はAuto、RECで固定し、最後の記録フレーム後にAutoへ戻す。次クリップへ固定値を持ち越さない。
- 関連用語: REC、ND案内、実適用値。ND完了を固定の契機にせず、合わせ直しでISO・絞り・シャッターを変えない。
- 参照先: [PRD FR-04](product-requirements.md)、[機能設計 S2](functional-design.md#s2-撮影制御解析ズームの独立状態)。

### 音量・入力有効性・音声障害

- 定義: 音量は信号レベル、入力有効性は必要な音声データが届く状態、音声障害は入力不能等の確認済みの問題。書込結果も別に扱う。
- 開始・遷移: 初期化・再接続は確認中。有効確認後に準備条件を満たし、確認済み障害では開始禁止または録画停止へ進む。復旧後は本人のRECを待つ。
- 本プロジェクトでの使用: 静寂・レベルゼロを障害と断定せず、音割れと入力障害も区別する。メーターが動いても正常保存の証明にはならない。障害判定・復旧の承認済み暫定policyと実機採用を分ける（U7）。
- 参照先: [PRD FR-09](product-requirements.md)、[機能設計 D1・S1](functional-design.md)。

### 保留・待機・結果不明・確認が必要

| 用語 | 定義と開始条件 | 終了・遷移条件／区別 |
| --- | --- | --- |
| 保留（ND等） | 入力遅延・根拠不足等により現在の評価を出せない状態 | 有効な入力と根拠で再評価。古い許容判定を残さない |
| 待機（通信等） | 指示済み処理に実行を妨げる条件がある状態 | 全抑止条件と本人意思を再照合。失敗確定・未指示と区別 |
| 結果不明 | 副作用が成立したか、証拠や対象の対応からまだ確定できない状態 | 実体・操作記録・必要な外部結果の照合で確定。未実行や失敗へ丸めない |
| 確認が必要／照合が必要 | 削除・写真登録等の結果を確定する照合が残っていることを示す表示 | 対応証拠の確定まで維持。本人の軽量プレビュー明示確認を求める語とは別 |

参照先: [機能設計 S2〜S7・エラーハンドリング](functional-design.md)、[開発ガイドライン「エラーハンドリング」](development-guidelines.md#エラーハンドリング)。表示文言は対象の操作名と併記し、「確認済み」の一語へ統合しない。

### 独立した状態軸

以下は一撮影に併存する別の事実。ある行の成功を別行の成功へ転用しない。状態値は[機能設計 D3〜D7・S3〜S7](functional-design.md#データ契約)の論理表現である。

| 状態の対象 | 定義・主な状態 | 確定条件・関連用語 |
| --- | --- | --- |
| 原本保存結果 | 記録中、確定処理中、正常保存、部分保存、結果不明、失敗 | 正常保存は書込終了と必要な音声・映像を含む対象検査・記録で確定。部分保存は一部の正常区間だけ確定できた状態 |
| 原本所在・削除結果 | 原本あり、削除中、削除済み、未削除、照合必要、参照不可等 | 実ファイルと記録で判定。削除済みには容量整理／破棄の目的を付ける。保存結果とは別 |
| Mac mini保存検証 | 未検証、待ち、検証済み（`verified`）、失敗、不明 | 全内容に対応する保存検証証拠による。送信完了とは別 |
| 軽量版の生成・公開 | 未生成、生成中、失敗、利用可能、差し替え保留 | 候補の生成成功と正式版の公開を分ける |

| 「写真」登録 | 未指示、取得中、登録中、登録成功、失敗、照合必要等 | 「写真」の結果と対応記録で確定。過去の保存成功と現在の存在も別 |

### 動画通信・既開始処理・再開

- 定義: 動画通信は原本送信、軽量版取得、軽量プレビューのストリーミング／一時取得を含む本体データの送受信。「既開始処理」は本人の開始指示が受理され、操作として保持されている処理。ネット実行前の指示済み順番待ちを含み、選択しただけの未指示動画とは区別する。
- 開始・停止: 新規の原本転送・「写真」保存はWi-Fi時だけ受理し、Wi-Fi不在時に未指示動画の開始予約を作らない。REC、録画、保存・異常終了処理、Wi-Fi不在等で動画通信を抑止する。
- 条件付き自動再開: 本人が開始受理済み・未完了・未停止／未キャンセルの通信だけ、Wi-Fi・REC／録画・保存等の全抑止条件、認証・接続、同一対象・版、既完了結果、本人意思・操作の寿命を再照合して自動再開する。指示済み順番待ちも同じ条件とし、録画終了だけでは再開しない。
- 本人停止・全件停止: 個別停止/再開/取消と、指示済み順番待ち/自動待機を含む全件媒体停止を区別する。本人停止は回線復帰・REC/保存終了・再起動で解除せず、全件媒体停止を全通信遮断と同一視しない。
- 背景・失敗: OSが許す既開始upload/downloadの背景/画面ロック継続を対象とする。個別失敗は独立動画を続行し、認証/回線/store等の共通問題は影響する集合を待機する。処理順/配置・寿命/期限等の具体値と、通常strict開始/resume・全媒体producerの成立は別に扱う。
- 媒体なし状態同期: 保存/検証/変換結果・版・既存確認/失効の事実を媒体本体なしで照会する別gate。モバイル回線でも許可し、新確認や媒体開始を生成しない。S28の既存登録・既知原本向け明示1page/続きを指す場合は、未解決失効とcursorを分離し再openはnullから照合する。元mutation/旧outbox、await後のexact登録/storeを維持し、未知背景ownerの対象ACKは保留する。再登録全体や通常媒体UIの完成を意味しない。
- 適用範囲: 未実行削除、結果不明の「写真」追加、終了済み再生を自動再実行する規則ではない。取得済みローカル再生とMac mini側の開始済み変換は動画通信の停止と区別する。
- 関連用語: 待機理由、操作ID、MediaIOGate、取消し・実停止。
- 参照先: [PRD FR-11・FR-15・FR-16](product-requirements.md)、[機能設計 D8・S4](functional-design.md)。

## データ用語

各項目の主要情報は機能上の契約を説明する。論理名と実装名を区別し、採用済みschema/同writerの保存表現を本書だけで変更しない。

### 撮影項目・クリップ・撮影ID

- 定義: 一回の撮影を管理する単位を撮影項目（クリップ）とし、撮影IDで各成果物と状態を結び付ける。
- 主要情報: 撮影ID、撮影日時、長さ・容量、保存結果、ローカル参照、転送・検証・版・確認・写真登録への対応。日時は撮影時点を保持し、取得日時と区別する。
- 本プロジェクトでの使用: 一撮影一IDの設計。再送や派生版、容量整理で別撮影を増やさず、原本削除後も管理記録を保持する。通常一覧/破棄成功履歴の具体配置等はU1。通常30秒・時々2〜3分は利用傾向で、録画上限ではない。
- 関連する論理名・参照先: `ClipRecord`、[機能設計 D3](functional-design.md#d3-撮影項目とローカル原本)。

### 原本同一性・映像同一性

- 定義: 原本同一性は保存・転送・削除対象が同じ原本全内容に対応すること。映像同一性は軽量版の再生・確認対象が同じ映像に対応すること。
- 主要情報: 原本ID・内容世代・全内容の照合情報、軽量版の映像ID・出力内容の照合情報。ファイル名・サイズ・日時・URLや変換設定名だけで成立させない。
- 本プロジェクトでの使用: 同じ映像の再取得では確認を維持する。同じ設定で再生成しても同一映像の証明がなければ別版として扱う。全内容識別にはサイズとSHA-256を採用し、内容世代・固定FD/read lease等と照合する。内部方式の採用を実撮影原本・実機保護/品質の受入へ拡張しない。
- 関連用語・参照先: 保存検証、版、[機能設計 D3・D4](functional-design.md)、[アーキテクチャ「内容同一性・保存証拠」](architecture.md#内容同一性保存証拠)。

### 保存検証・保存検証証拠

- 定義: 保存検証はMac miniに確定保存された原本全体が対象原本と整合することの検証。保存検証証拠は、その原本対応・保存完了・検証結果を示す記録。
- 主要情報: 原本同一性、保存・全内容検証結果、証拠の版、取得時点。HTTP成功や送信側digestの単純な返却では成立しない。
- 本プロジェクトでの使用: `verified`は証拠を持つ保存検証済み状態。接続失敗で既知の成功を失敗へ変更しない一方、後から得た消失・失敗等の確定情報は反映する。オフラインでは取得後の外部変化を保証できない。
- 関連する論理名・参照先: `StorageVerification`、[機能設計 D4](functional-design.md#d4-mac-mini保存検証軽量版)、[アーキテクチャ「内容同一性・保存証拠」](architecture.md#内容同一性保存証拠)。

### 版・映像ID・公開版・候補版

| 用語 | 定義・主要情報 | 関係・使用上の注意 |
| --- | --- | --- |
| 版／変換版 | 軽量版の出力と変換条件を識別する区分 | 原本・映像ID・変換仕様の版・入力Log種別・出力照合情報を対応させる |
| 映像ID | 確認対象となる軽量版映像の識別子 | 取得URLとは別。同一映像の再取得と映像変更を区別する |
| 公開版／正式版 | FrameRelayが確認対象として利用する版 | 単に生成できただけのファイルと分ける |
| 候補版 | 生成済みでも、正式版への差し替えが未確定の版 | 存在だけでは公開版や旧確認を置換しない |
| V1／V2 | 差し替え例で旧公開版／新版候補を表す説明用記号 | アプリのリリース番号や、画面IDのV1撮影・V2撮影設定とは別 |

関連する論理名は`PreviewVersion / PreviewPublication`。参照先: [機能設計 D4・S5](functional-design.md)、[アーキテクチャ「Mac miniとの必要契約」](architecture.md#mac-miniとの必要契約)。

### 再生トークン・確認記録

- 定義: 再生トークンは確認操作と実際の再生対象・到達を結び付ける情報。確認記録は1本ずつの本人操作を同一原本・変換版・映像・確認世代へ対応させ、永続保存する情報。
- 主要情報: 前者は原本・変換版・映像ID、再生セッション、実再生到達、開始時の確認世代。後者は端末識別、原本・変換版・映像ID、明示操作時点、永続記録ID、確認世代・状態。
- 本プロジェクトでの使用: 通信再開時も同じ対象・版との対応を照合する。画面を開いただけでは再生到達にならず、`valid`は最新世代を照合し保存確定した後だけ使う。複数選択で確認記録を一括生成しない。再生媒体の解放や同一映像の再取得だけで有効記録を消さない。
- 関連する論理名・参照先: `PlaybackToken / ConfirmationRecord`、[機能設計 D5・S5](functional-design.md)。

### 確認失効・失効記録・差し替え

- 定義: 確認失効は旧映像の確認を容量整理の根拠として使えなくすること。失効記録は対象と世代・保存結果・応答状態を残す情報。差し替えは正式な軽量版を新しい映像へ切り替えること。
- 主要情報: 対象原本・旧映像、失効ID、世代、配布先登録、端末保存結果、登録別ACKの状態。失効IDは同じ要求の再送を識別する。
- 順序: 端末で失効tombstone＋ACK outboxを同writerへcommit→登録別保存成功ACK→サーバーで全必要ACKを再照合して差し替え確定。失効保存前のオフラインでは旧版と有効確認を維持し、保存後は応答消失・差し替え保留・再起動でも旧確認を復活させない。新版の再生・明示確認で新しい有効記録を作る。
- 全必要ACK: 旧版配布台帳から登録別に必要となる失効保存応答。本人確認が未同期でも配布先登録を含み、差し替え待ち中の旧版配布も必要集合へ加える。旧登録ACKを別/新登録ACKやtimeoutで代用しない。
- 再登録: 通常の再起動とは異なる新登録の成立。旧登録の必要ACKが得られなければ該当差し替えだけを無期限保留し、新登録の通常利用や独立動画を止めない。旧確認を自動復元せず容量整理対象だけ再確認する。全履歴再確認・一律原本再転送/再生成/写真再保存を通常利用条件にしない。
- 関連する論理名・参照先: `InvalidationRecord`、直列化、[PRD FR-13](product-requirements.md)、[機能設計 S5](functional-design.md#s5-明示確認失効と版の差し替え)。

### 操作ID・対象ID・世代

| 用語 | 定義・主要情報 | 本プロジェクトでの使用 |
| --- | --- | --- |
| 操作ID | 一つの開始意思と処理結果を結び付ける識別子 | 再試行・重複応答を元操作へ対応させる。撮影IDとは別 |
| 対象ID | 操作対象の撮影・原本・映像等を指定する識別子 | 何のIDかを明示し、別対象の応答を受け入れない |
| 内容世代 | 原本の内容がどの時点のものかを区別する更新情報 | 転送・検査・削除対象の一致を検証する |
| 確認世代／失効世代 | 確認の有効性や失効の順序を区別する更新情報 | 旧確認・古い応答で現状態を巻き戻さない |
| 設定・構図・対象選択の世代 | 解析入力がどの条件に基づくかを区別する更新情報 | 現条件と合わないND・人物・予告結果を採用しない |
| 試行世代 | 同じ操作の実行試行を区別する更新情報 | 再試行前の遅い結果を最新結果へ無条件に上書きしない |

時刻だけで版・世代の新旧を判定しない。具体ID型や採番方式は本書で追加しない。関連用語・参照先: 冪等性、期待世代、[機能設計 D1・D2・D8・共通の非同期処理規則](functional-design.md)。

複数操作はまとめて開始する本人の指示を識別するID・操作種別・受理時の固定対象集合と、動画別の操作ID・対象／版・状態を対応させる。開始受理後の順番待ちは指示済みであり、後から撮影・表示・選択した未指示動画を集合へ自動追加しない。成否・未処理は動画別に保持し、集合の成功値で個別結果を上書きしない。参照先: [機能設計 D8](functional-design.md#d8-非同期操作と再開条件)。

### ローカル原本参照・削除意図・削除結果

- 定義: ローカル原本参照はアプリ所有原本の固定された不透明な参照。削除意図は対象・目的・本人操作を削除前に記録したもの。削除結果は実ファイルと管理記録の照合で確定する結果。
- 主要情報: 原本同一性・内容世代・参照、操作ID、容量整理／破棄の目的、本人操作、証拠世代または提示リスク、実行・照合結果。
- 本プロジェクトでの使用: 外部URLや「写真」参照を削除対象へ変換しない。意図記録だけでは成功にせず、削除済み／未削除／確認が必要をローカルで復旧する。未実行意図を再起動時に自動実行しない。
- 削除境界: 全reader/実handle解放と予約・管理root/leafを照合し、同FD全hash後、同writerで最終条件を再判定してMOVだけをunlinkする。実不在/FD閉鎖と結果commitを照合し、復旧は観測だけとする。
- 終端履歴とfence: S34-BG01の単数リスク破棄で使う`OriginalRemovalTransportFence`は、対象のhistorical upload全task receipt集合とhash前inventoryを保持する一時的な照合値。同writer最終unlinkで再構築し、ABA/新attempt/task/関連登録変更を拒否する。対象に無関係な別clip更新は許し、fenceなし旧callerの全writer revision CAS（期待revision照合）とschema 7/Codable旧commandを維持する。未知/copy中/attach gap/旧source/再利用task/同operation複数attempt/download/活動中は保留し、自動停止・回収しない。通常cleanup/Photos/複数UIの完成を意味せず、原本unlink後もupload copyを保持する。
- 関連する論理名・参照先: `LocalOriginalRef / RemovalPurpose / RemovalIntent / RemovalResult / ReconciliationEvidence`、[機能設計 D6・S6](functional-design.md)。

### 写真登録キー・登録記録・一時コピー

- 定義: 写真登録キー（`PhotoRegistrationKey`）は撮影ID＋変換版ID（`RenditionID`）の組で、同撮影・同変換版の二重追加を抑止する。登録記録は動画別の操作と「写真」の結果を対応させる情報。一時コピーは再生や登録のために取得する軽量版媒体で、TemporaryMediaはストリーミングバッファも扱う。
- 主要情報: キーとは別に、完全な原本/映像/内容を含む`RenditionIdentity`と撮影日時を登録意図へ固定し、同writerで照合する。同じ変換版IDを別内容へ付け替える再試行も拒否する。動画別操作ID・対象集合、登録状態、取得可能な写真側参照・証拠、一時媒体の用途・取得範囲・検証状態・所有者・使用権・解放可否・使用量を対応させる。
- 本プロジェクトでの使用: 同じキーで登録を直列化する。写真側参照の欠落だけで再追加せず、過去の登録結果と現在の存在観測、結果不明の照合記録と媒体本体を分けて保持する。部分バッファを完全な登録用ファイルや原本検証証拠にせず、空き容量不要とは扱わない。
- 権限・照合限界: 保存時はaddOnly、必要な不明結果等の照合時だけ対象/理由を示してreadWriteを案内する。拒否・限定・対応不明・未発見を未保存や再追加許可へ変えず、無条件再追加/写真側削除後の自動復活をしない。手動再保存/アルバムはU2の未合意事項。
- 終端・解放・回収: Photosの実SDK非開始または完了とFD閉鎖を元intent/use・owner/epoch・ファイル同一性とexact commitへ束縛し、その元useだけを登録結果と独立に解放する。再生専用データは使用終了後に回収し、Photos登録用コピー本体のunlinkは登録成功かつ全使用権解放後とする。unknown/failed/notAttemptedの本体・identifier/再追加抑止・照合証拠を保持し、従来の成功recordによる限定回収も維持する。本体回収でも確認記録・登録履歴・照合証拠を消さず、保持容量/期限・未知copy回収等の未合意policyを追加しない。
- 関連する論理名・参照先: `PhotoRegistrationKey / PhotoRegistration / TemporaryMedia`、使用権、[機能設計 D7・S7](functional-design.md)。

### 論理層・Port・Adapter・Composition

| 用語 | 定義と本プロジェクトでの用途 | 関係 |
| --- | --- | --- |
| Presentation | 表示用の値と本人入力を扱う責務 | `Features/`等に実在し、I/Oや削除規則を直接実行しない |
| Application | 撮影・媒体操作・復旧等の順序と状態所有を調停する責務 | Domainの規則とPortを利用する |
| Domain | 値と副作用のない製品規則を扱う責務 | 時刻・能力・証拠を入力で受け、UI・DB・端末APIに依存しない |
| Platform | 端末・保存・通信・再生・Photos等の具体I/Oを扱う責務 | Portを実装し、外部表現を境界内へ閉じる |
| Port | Applicationから利用するI/Oの契約 | protocolや値契約は`Application/Ports/`に置き、具象SDK/外部DTOを漏らさない |
| Adapter／Service | Portを具体技術へ接続する実装 | 具体名はarchitectureの採用状況と実配置に対応させる |
| Composition | 具象実装を生成して契約へ注入する組み立て箇所 | 規則や独自の成功判定を置かない |
| command／event／snapshot | 実行要求／型付きの発生事実／表示等に渡す値のまとまり | 担当間の窓口。snapshotや表示キャッシュを永続証拠の正本にしない |

各層は同一App module内の論理境界であり、別target・packageの採用や自動的な依存強制を意味しない。`CaptureCoordinator`、`MediaOperations`、`OperationStore`、`Library`、`Recovery`等の責務名と実型名を区別し、実在配置はリポジトリ構造を参照する。

参照先: [アーキテクチャ「システム境界」](architecture.md#システム境界)、[リポジトリ構造「依存関係」](repository-structure.md#依存関係)。

### commit・期待世代・直列化・冪等性

| 用語 | 定義と本プロジェクトでの使用 | 保証の境界 |
| --- | --- | --- |
| commit成功 | Portが永続storeへの保存成功を確認した段階 | UI受付、子contextのsave、HTTP成功では代用しない。Gitのcommitとは文脈を分ける |
| 期待世代 | 更新が前提とする対象の世代 | 保存時に現世代と照合し、古い更新や二重commitを拒否する |
| 直列化／項目排他 | 同一対象の競合操作を一つの順序で実行すること | 原本単位の削除・失効、写真登録キー単位の登録に使用。`await`付きactorだけで操作全体の排他が完成したとしない |
| 冪等性 | 同じ操作を繰り返し受けても追加の副作用や状態矛盾を生まない性質 | 操作ID・失効ID・元mutation等で照合する。隔離技術証拠を稼働MediaVault全体の成立へ拡張しない |

### 使用権・lease・MediaIOGate・取消し

- 定義: 使用権/leaseは媒体やI/Oを用途・操作・ownerへ束縛して管理する契約。原本read lease、軽量版scopeの使用権、一時コピーのphoto/retrieval用途、通信開始のpermitを区別し、一つの解放を他用途の全解放にしない。MediaIOGateは全動画通信の許可と抑止理由を扱う論理責務。
- 本プロジェクトでの使用: 原本削除や一時コピー回収は必要な全reader/実handleの解放を照合する。原本read leaseは内容/操作/owner/epoch・実FD/SDK attachmentと対応させ、軽量版/一時媒体は完全な版・用途・範囲・使用者を保持する。通信はWi-Fi・REC/保存・本人停止等を独立に保持し、原本lease取得だけで通信開始を許可しない。
- SDK実終端・ownerClosed: 実completion等で対象SDK操作の終了を観測することと、owner自身の保持資源を閉鎖して記録することを分ける。背景uploadではexactなOS session/task/attemptの実SDK終端→ManagedUploadSource自身の保持FD閉鎖→ownerClosed commit→exact lease解放→stoppedを照合する。SDK所有全FDの閉鎖やMac未実行まで証明せず、試験で注入したstrict permit/Mac notExecutedを実ネットワーク観測値としない。
- 未知の所有者: 再起動後の旧source、copy中/attach gap、活動中task等で実終端/解放の証拠がなければ保留する。task一覧の不在・finishEvents・配送handler完了から全reader解放を作らず、元useの解放とコピー本体の回収条件も分ける。
- 取消しの区別: 要求受付、端末上の実停止、外部副作用の結果は別イベント。task取消し・画面離脱でMac保存やPhotos追加まで取り消せたとは扱わない。
- 関連用語・参照先: 直列化、動画通信、[アーキテクチャ「並行処理・寿命・キャンセル」](architecture.md#並行処理寿命キャンセル)、[「全動画通信の共通契約」](architecture.md#全動画通信の共通契約)。

### DIの実装状態・4軸・局所保留・部分引渡し

DI（実機なし先行実装）の4段階は共通保存/原本/一覧、連携/媒体制御、Photos/削除、撮影/補助表示の変更単位であり、次の実装状態とは別の分類である。

| 実装状態 | 定義・区別 |
| --- | --- |

| 軸 | 対象/版ごとに記録する意味 |
| --- | --- |
| I（実装） | 実装状態と必要接続・未接続・暫定値の範囲 |

- 定義: 品質ゲートは変更範囲に必要なbuild・診断・test・起動・実機等の確認。証跡は対象/版・条件・実施結果・判定を追跡できる記録で、通常mainレビュー・専門文書レビュー・独立validationも実行証拠と分ける。
- 本体task Doneと製品DoD: 前者は割当てた本体/必要接続・全substatus/Finish・必要な意味ある試験/build/実I/O/UI・mainレビューの完了。必須検証失敗/未実行があれば当該taskをdoneにしない。後者は全21要求・79AC全文、必要な実機/実通信・事前品質合意・実データ条件の充足で別に判定する。独立した本体の完了を製品全体の受入へ読み替えず、当該taskに必須の実機検証も免除しない。
- 本プロジェクトでの使用: 文書だけの変更はリンク・構造・正本との整合・差分範囲を静的確認する。アプリ変更は実在project、scheme、destination、対象testを確認してから実行する。固定カバレッジ閾値は未合意。
- 関連用語: targetはビルド対象、schemeは各actionの実行構成、destinationは実行先。target名からschemeを推定しない。build成功、起動確認、試験実施、受入合格を分ける。
- 参照先: [開発ガイドライン「品質ゲート」「Definition of Done」](development-guidelines.md#品質ゲート)。

### 旧MediaVault原本・試験データ整理

- 定義: 旧MediaVault原本は開発中のMac mini変換・軽量プレビュー試験に用いる既存動画。試験データ整理は、合意した対象と方法で開発用データを片付け、結果を記録する作業。
- 本プロジェクトでの使用: FrameRelayの転送試験には新規撮影原本を用いる。旧「写真」原本削除や汎用移行は前提にしない。既存実原本・本番相当記録の削除・上書きは対象と操作への別の明示合意を必要とする。
- 関連用語: NFR-04、実施、証跡。製品機能としてのFR-14容量整理とは別の開発作業。
- 参照先: [PRD NFR-04](product-requirements.md)、[開発ガイドライン「テスト戦略」](development-guidelines.md#テスト戦略)。

## 廃止語・表記揺れ

先行文書を一律に書き換えるものではない。同義表記は下表で意味を対応させ、異なる概念を一語に縮めた表現を避ける。R2で置き換えた旧制約以外に、製品用語を新たに廃止する判断はしない。

| 使用しない表記・区別する表記 | 正式表記・推奨する書き分け | 理由・移行方針 |
| --- | --- | --- |
| プレビュー（対象不明） | 撮影プレビュー／構図予告／Rec.709軽量プレビュー | 現在映像、未来の範囲目安、保存後の確認用動画を区別 |
| 軽量版／軽量プレビュー | 成果物はRec.709軽量版、確認用途は軽量プレビュー | 同じ動画の用途差。初出ではRec.709を明示 |
| 原本／Log原本／iPhone原本／ローカル原本 | 所在を区別するときはFrameRelay内のiPhone原本／Mac mini原本 | 「原本」だけで削除先を曖昧にしない |
| 原本削除＝管理記録/一覧から消去 | 原本本体の実削除／管理記録保持／整理成功は通常一覧 | 媒体本体・記録・表示分類を分ける |
| 破棄履歴＝ゴミ箱 | 照合済み破棄成功の管理履歴 | 原本本体を移して保持せず、不明結果を履歴へ隠さない |
| 確認済み（対象不明） | 保存検証済み／軽量プレビューの明示確認済み／破棄対象と消失リスクの確認 | 機械検証・本人の映像確認・破棄意思を分ける |
| 確認が必要＝再視聴が必要 | 対象処理の結果照合が必要 | 結果不明からの復旧をFR-13の確認操作と混同しない |
| 削除／整理（目的不明） | 容量整理（FR-14）／不要動画の破棄（FR-17） | 同じローカル削除でも目的・許可条件を分ける |
| 未転送・未確認の原本は一切削除不可 | 容量整理は不可。不要動画の破棄は本人の対象・消失リスク確認で扱う | R1の旧制約をR2が置換。旧制約を現行要求へ戻さない |
| 削除候補＝削除許可・予約・削除済み | 容量整理の条件を満たす導出状態 | 本人操作・直前再判定・実削除結果が別に必要 |
| 送信完了＝検証済み | 送信完了／Mac mini保存検証済み | HTTP成功は全内容検証の証拠ではない |
| 再生済み＝明示確認済み | 実再生到達／本人操作／確認記録確定 | 三つの段階を分ける |
| 取得済み＝「写真」保存済み | 軽量版取得完了／「写真」登録成功 | 外部登録と対応記録が必要 |
| 「写真」保存履歴＝現在も存在 | 登録成功の履歴／現在の存在確認 | 後日の本人削除・権限制限を区別 |
| 再生成＝差し替え | 候補版生成／失効保存／正式版の差し替え | 生成だけで旧確認を無効化・置換しない |
| 同じURL・変換名＝同じ映像 | 映像同一性を証明した同一版 | 証明できなければ別版扱い |
| 追跡OFF＝ピント固定 | 追跡OFF時の人物優先AF | FR-05の動作を維持 |
| 引き伸ばしなし＝完全無劣化・最良画質 | 条件と根拠を持つ停止候補 | 倍率だけで実画質を保証しない |
| キャンセル済み＝外部操作未実行 | 取消し受付／実停止／副作用の結果 | Mac保存・Photos追加等の結果を照合する |
| lease解放＝コピー回収／全reader解放 | 用途別使用権解放／本体回収条件／全ownerの実終端 | 元useの解放だけで他用途・SDK内部・媒体本体の回収を推定しない |
| 新登録ACK＝旧登録の必要ACK | 登録別の全必要ACK | 再登録で旧登録の差し替え保留を自動解除しない |
| Photos／PhotoKit／「写真」 | 機能・保存先は「写真」、技術境界はPhotos／PhotoKit | 製品操作とAPIを区別 |
| commit（対象不明） | 永続storeへのcommit／Git commit | 保存確定と変更履歴の操作を区別 |
| 確定・対応済み・完了（根拠不明） | 要求承認／設計案／実装済み／試験実施／受入合格を明記 | 合意と実機成立を混同しない |
| Swift 5.0＝コンパイラ版 | Swift言語モード5.0 | 使用コンパイラ・Xcode・SDKは別途確認 |

更新時は用語の根拠文書・意味・関連語を併せて確認し、矛盾は用語集だけで解決しない。構成と記述基準は[glossary-creation Skill](../.agents/skills/glossary-creation/SKILL.md)、[テンプレート](../.agents/skills/glossary-creation/assets/template.md)、[ガイド](../.agents/skills/glossary-creation/references/guide.md)に従う。
