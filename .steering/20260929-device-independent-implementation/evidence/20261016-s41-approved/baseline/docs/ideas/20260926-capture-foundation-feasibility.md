## Background

合意済みの撮影条件が手持ち実機でどのように成立するかを、本格的な機能の作り込みに先立って確認する。PRDのQ01と必須技術検証ゲートを具体化し、形式・手動制御・WB・音声・表示・補正・ズーム／レンズ切替を組み合わせた際の成立条件、制約、未解決事項を証拠付きで整理する。

資料や能力照会だけでは、音声付き保存動画、実適用設定、録画継続性、品質を確認できない。このため、後続工程で既存FrameRelayプロジェクト内に必要最小限の検証実装と操作画面を用意し、実機・保存動画・適用設定・ログを照合する。製品用UIや基本撮影機能全体の完成を、今回の検証工程の完了条件にしない。

全P0の21要求・79受入条件と禁止動作を維持する。工程を分けることは初期版の対象範囲を減らす決定ではなく、本書で扱わない機能も後続の必須事項として追跡する。不成立の要求は未達のまま残し、制約・代替案を示して相談する。

## Target Users / Use Cases

- 検証を操作・評価する本人と、後続計画・実装・検証を担当する開発者。
- 本人が家族・旅行を高品質で撮影する際の設定、手持ち・歩き撮り・ゆっくりしたパン、寄る／引くズーム、レンズ切替、連続撮影を代表場面とする。人物AFやND案内そのものの品質評価は後続に残す。
- 通常30秒程度、時々2〜3分という利用例を、保存・継続性・応答性の評価に使う。これらを録画時間の上限にしない。
- 手持ち実機は本人申告の **iPhone 18 Pro**。ストレージ容量、実際のiOSバージョン、現在の空き容量は未確認であり、試験開始前に実値を記録する。機種名から可変絞りや特定の形式・補正の対応を推定しない。

## Scope

本節は後続工程で行う技術検証の範囲であり、今回の文書保存で実行を開始するものではない。

- 既存FrameRelay内の最小限の検証実装・操作画面。条件選択、REC／STOP、検証に必要な設定操作、実適用値・音声状態・保存結果の表示、保存動画を確認できる手段を含む。
- 各カメラの4K・24／30fps・ProRes 422 LT／422／422 Proxy＋Apple Logの組合せ、実際のLog種別、絞りの有無・制御可能性、手動設定の維持。
- RECに連動したWB固定、明示的な合わせ直し、記録終端と次クリップのAuto復帰。
- 音量と入力有効性・音声データ到着・書込結果の区別、障害時の開始抑止／停止、保存可能な部分の確定、復旧後の手動REC。
- 固定標準Rec.709撮影プレビュー、原本への非焼き込み、表示と録画の両立。
- OFFと程度・特性の異なる複数の手ブレ補正モード、実適用、対応条件付き設定復元、画角・音声同期・録画継続性。
- 録画中の寄る／引くズーム、目標での停止・途中停止、レンズ切替と限定的なISO補正、実カメラ・設定維持、選択した補正との両立。
- アプリ内原本保存と、録画・保存境界の中断／復帰／再起動後の結果照合。
- 初回権限取得・通常起動・復帰、REC受付から実記録開始、次のRECまでの応答性と、上記機能の同時成立。
- 組合せ別の証跡、原因切り分け、品質判定、未解決事項、PRDへの対応と後続必須事項の整理。

- 製品ライブラリ全体、原本転送、Mac mini保存検証、変換、軽量版再生・明示確認・失効、写真保存、容量整理、不要動画の破棄、実通信と録画の競合検証。いずれもPRDのP0から除外せず、後続で実装・受入検証する。
- 既存MediaVaultの実行調査、旧実原本の変換・転送・削除・移動・上書き、試験データの整理作業。本書の保存はこれらの実データ操作を許可しない。
- 未合意の製品UI・数値・方式の新規確定。ズーム速度・停止許容差、ISO補正上限や戻り時の基準、補正モード名・具体的な数・強さ、音声障害の猶予・復旧回数、熱・容量の閾値、採用Log種別等を固定しない。
- 独自のproject／workspace生成、別検証アプリ、外部依存・外部ツールの導入、既存の最低対応iOS・Swift言語モード変更。具体API・クラス・ファイル構成・DB・内部アルゴリズムを本書で新規選定しない。

PRDの対象外・禁止動作は引き続き適用する。後続必須の機能を「初期版対象外」や任意機能へ読み替えない。

## User Flow

1. **計画する**: 本仕様を入力に、後続の計画で最小実装の範囲、試験ケース、実行前提、比較・反復条件、証跡の保管と照合方法を具体化する。品質合格に使う評価条件・方法・許容範囲はユーザーと事前に合意する。必要な承認を得てから実装・実機試験へ進む。
2. **環境を記録する**: 実機の機種・容量・iOS・空き容量、Xcode／Swiftコンパイラ／SDK、実装版を確認する。カメラ・マイク・保存先の準備状態と権限を記録する。未確認値を架空の値で埋めない。
3. **組合せを選ぶ**: ケースIDと希望条件を選び、能力照会結果と現在の実適用値を確認する。未確認・非対応・適用失敗を区別し、無断で別条件へ置き換えない。
4. **記録する**: 必要な記録条件が整ったら本人がRECを押す。実記録開始を確認し、ケースに従ってWB合わせ直し、ズーム、停止、レンズ切替等を行う。希望値・実値・操作とイベント時刻を対応付ける。
5. **停止・保存結果を確認する**: 本人のSTOPまたは確認済み障害で停止する。音声・映像を含む実ファイル、保存結果の記録、表示を照合する。復旧しても自動RECせず、次の撮影は本人の操作で行う。
6. **評価・切り分けを行う**: 保存動画と実機操作を比較し、単独条件と同時動作の結果を整理する。失敗時は再現・比較・資料上の制約等を調べ、根拠の範囲で原因を分類する。
7. **工程と要求を別々に判定する**: 必須ケースの実施状況と残件から検証工程の完了を判断する。各PRD受入条件は別に評価し、不成立・未評価・未合意・未測定を達成済みにしない。制約と代替案を相談し、後続必須事項へ引き継ぐ。

## Functional Requirements

本書固有の要求を `CF-xx`、受入条件を `AC-CF-xx` とする。PRDの要求IDや受入条件IDを置換しない。

### CF-01 検証環境と最小限の操作画面

- 後続の計画・承認後、既存FrameRelayプロジェクトで実機から操作できる検証実装を用意する。資料調査、能力一覧、Simulator、テスト用代替だけでは検証工程を完了しない。
- 操作画面でケースと条件を選択し、REC／STOP、手動値の変更、WBの明示的な合わせ直し、補正選択、ズーム／レンズ切替等を試せる。配置・ジェスチャー・製品向け名称は確定しない。
- 希望条件、実適用値、準備中／開始中／実録画中／停止・保存中、音声状態、保存結果、操作できない理由を識別できる。設定の選択やREC受付だけで適用済み・記録開始済みを表示しない。
- 保存動画とケースの対応を保ち、対象動画の再生・映像／音声の確認を行える。最小限の確認手段を製品ライブラリ完成へ読み替えない。

### CF-02 形式・カメラ能力・手動制御

- 各カメラについて、4K、24fps／30fpsそれぞれ、ProRes 422 LT／422／422 ProxyとApple Logの組合せを対応表にする。機種名だけでカメラ数・絞り・形式対応を確定しない。
- 標準のLT、上位の422、容量優先のProxyというPRDの希望を維持する。実際に選択・適用・保存されたLog種別を記録し、Apple Logの種別や変換の採用を名称だけで決めない。
- 希望値、能力照会の結果、実適用値、保存ファイルの形式・解像度・fps・色特性・音声の結果を分けて照合する。能力照会の成功を録画成立の証拠にしない。
- シャッター、通常時の手動ISO、対応する絞りが維持されるか確認する。180°・特定ISO・特定F値を固定要求にしない。非対応カメラの絞りを操作可能として表示しない。
- 保存済み設定を再利用する場合も現在条件を照合する。WBはCF-03、補正はCF-06に従い、非対応や未確認の設定を無断適用・代替しない。
- 標準形式が成立しない場合は対象組合せと根拠、制約、代替案、要求再確認の必要性を示す。別形式の成功で標準要求を達成扱いにしない。

### CF-03 REC境界のWB

- 起動・待機中はWB Autoとし、REC時点で取得できている値を固定する。WBの安定待ちを開始遅延の条件にしない。ND完了を固定の契機にしない。
- 録画中は本人の明示的な合わせ直しでのみ更新・再固定する。ISO・絞り・シャッターを勝手に変えず、色変化と録画継続性を記録する。
- REC受付、実記録開始、最初／最後の記録フレーム、WBの変化を照合する。最後の記録フレームまで固定し、停止後の待機ではAutoに戻るか確認する。
- 連続して二本撮影し、前クリップの固定値の持ち越しではなく次クリップで新たな測定が行われるか確認する。

### CF-04 音声・障害停止・復旧

- 待機中・録画中の音量メーター、入力有効性、音声データ到着、書込結果を別の観測にする。静寂・小音量・音割れ・入力確認中・確認済み障害を混同しない。
- 静寂やレベルゼロだけで開始禁止・停止にしない。確認済み入力障害はメーター付近の赤い×と理由等で示し、色だけに頼らず次の操作を識別できるようにする。
- REC前の確認済み障害では無音で開始せず、録画中の障害では停止し、保存可能な部分の確定を試みる。実録画が止まっているのに録画継続中と表示しない。
- 保存結果と復旧結果を分ける。復旧後は本人のRECを待つ。無限再試行・全体自動再起動・動画削除やアプリ削除を通常復旧手順にしない。
- 障害判定の猶予、試行回数・時間、再構成範囲は未合意のまま固定しない。後続計画で対象ケースと試験条件を明示する。メーターの動きだけで保存成功を判定しない。

### CF-05 固定Rec.709撮影プレビュー

- 待機中と録画中の両方で、撮影するLog形式に対応する固定標準Rec.709表示を確認する。未変換Log表示だけを成立としない。
- 表示変換が保存Log原本へ焼き込まれていないことを、実ファイルと表示条件の対応から確認する。採用Log種別・具体変換方式は後続で扱い、LUT選択UIを追加しない。
- 表示の描画性能と音声付き録画の安定性を同時に観測する。撮影プレビューの閲覧を、FR-13の軽量プレビューの明示確認へ転用しない。

### CF-06 手ブレ補正と設定復元

- 待機中にOFFと程度・特性の異なる複数の補正モードを選び、対応可否と実適用が一致するか確認する。モード名の表示だけ、OFFだけの成立をFR-03達成にしない。
- 初回は対応確認した標準相当を第一候補とし、以後は前回の選択を対応する条件で復元する。現在条件で非対応なら制約を示し、本人がOFFまたは対応モードを選ぶ。無断置換しない。
- カメラ・解像度・fps・コーデック・Log形式との組合せを区別する。歩き撮り、静止した手持ち、ゆっくりしたパンで保存Log動画の補正効果、画角・構図、音声同期、録画継続性を確認する。
- 録画中のズーム・レンズ切替で選択した補正を維持できる条件を確認する。録画中の手動補正切替は必須に追加せず、アプリ判断でモード・強さ・録画形式・手動制御方針を変えない。FR-08の限定的ISO補正は維持する。
- 画角変化の観測結果を、後続の構図予告・ズーム停止支援へ引き継ぐ。これらへの反映・品質合格が未実施ならAC-FR-03-04全体を達成にしない。

### CF-07 録画中ズーム・レンズ切替

- 試験用操作でゆっくり寄る／引く、目標での停止、途中停止を行い、目標値と実倍率の変化を照合する。速度・操作方式・吸着・停止許容差を製品仕様として確定しない。
- レンズ切替の前・中・後に、実カメラ、ISO、シャッター、fps、WB、補正等を記録する。通常時は手動ISO、切替中だけ限定的補正、切替後は補正後の値維持というPRD方針との一致を確認する。
- 常時Auto ISOへ移行せず、シャッター・fps・WB方針を露出合わせで無断変更しない。戻り時ISO・補正上限・手動変更後の基準は試験ごとの比較条件として後続で明示し、製品採用と分ける。
- 保存動画と実操作から、途切れ、明るさ・色・ピント・位置の変化、切替時間、音声同期、録画継続性、ズーム中と停止後の画質を区別して記録する。
- 非対応の組合せや、選択した補正を維持できない切替を無通知で実行しない。録画を失敗させてまで切替を優先しない。成立しない場合は制約・代替案を提示する。
- 整数倍率だけを高画質の根拠にせず、引き伸ばしなしを完全無劣化・最良画質の保証にしない。構図予告・画質に基づく停止支援の完成は後続必須事項として残す。

### CF-08 ローカル保存・中断・復旧

- 音声付き原本をFrameRelay内に保存し、同じ原本を「写真」へ追加しない。STOP受付・記録停止と、ファイル確定・結果記録を別に観測する。
- 正常保存、部分保存、結果不明、失敗を区別する。ファイルがあるだけ、録画表示が終了しただけで正常保存にしない。
- 後続計画で定めた録画・保存の境界で中断／復帰／再起動を試し、実ファイル、保存結果の管理記録、表示を照合する。診断ログを復旧結果の唯一の根拠にしない。
- 記録・権限・容量等の問題がある場合は、原因と保存結果、次に取れる操作を分けて示す。部分保存の救済成功や、背景・画面ロック中の録画継続を未検証のまま保証しない。
- 中断前の表示だけで録画中へ復元せず、自動RECしない。容量不足や復旧を理由に原本を自動削除しない。

### CF-09 応答性と同時成立

- 初回権限取得、通常起動、復帰を区別し、撮影可能まで、REC受付から実記録開始まで、停止後の次RECまでを実機測定する。通常起動2〜3秒はPRDの目標として扱い、達成条件と制約を記録する。
- 音声省略や無断の形式・設定変更で時間目標を達成扱いにしない。WB安定待ち、ND警告・解析遅延だけを録画開始禁止の理由にしない。
- **標準形式＋手動制御＋WB＋音声＋固定Rec.709表示＋補正＋録画中ズーム／レンズ切替**を組み合わせ、単独成功だけでは見えない制約を確認する。各24／30fpsとカメラ・補正条件を結果に対応付ける。
- 代表的なクリップ長と連続撮影で、保存・表示等が記録と次RECへ与える影響を記録する。熱・容量による制約を見つけた場合も、未合意の閾値や自動負荷対策を確定しない。
- 通信停止・再開のRECへの影響、人物／ND解析・構図予告等を統合した際の品質は後続に残す。今回の測定だけでNFR-01・NFR-03全体の達成を主張しない。

### CF-10 組合せ別の証跡と結果分類

ケースごとに以下を対応付ける。詳細ケース・反復条件・比較方法・証跡の配置は後続計画で列挙し、必須ケースと依存関係を追跡する。失敗後に都合の悪い条件を対応表から削除しない。

| 記録項目 | 必要な内容 |
| --- | --- |
| 識別と環境 | ケースID、実施日時・実施者、機種、iOS、Xcode／Swiftコンパイラ／SDK、実装版、ストレージ容量・空き容量 |

### 検証工程の完了判定

本仕様の技術検証工程を完了とするには、実行可能な必須ケースを実機で実施し、上記受入条件に沿った観測・照合・切り分け・引継ぎを行う。資料調査だけでは完了しない。未着手、実機や環境の不足、未整備の検証手段等で必須検証が残っている場合は、未実施として残し工程完了に置き換えない。

根拠のある前提不成立で録画等を実施できない組合せは、その根拠と依存する未実施を明示する。検証した結果の不成立・品質不適合・原因未確認は、要求を未達／未評価として残し、影響・代替案・追加調査・判断事項を整理する。原因未確認のまま非対応を断定したり、失敗記録だけを揃えて調査完了としたりしない。

工程完了の報告には、実施した範囲と実施不能の根拠、未達要求、後続必須事項を含める。PRD受入達成は、対応する全条件と事前合意した品質許容範囲を証拠付きで満たした場合に別途判定する。今回の工程完了は、基本撮影機能全体や初期版全体の完成を意味しない。
