# 機能設計ガイド

## 責務の分解

- 画面・View: 表示、利用者入力、アクセシビリティ、再利用可能な表示。
- 状態の所有・更新: 状態遷移、非同期処理、画面とロジックの接続。
- ロジック: UIや端末APIへ依存しない規則と計算。
- サービス: iOSの端末機能、永続化、外部I/O。

各要素について責務、入力、出力、依存先、失敗時の振る舞い、禁止事項を書く。状態の所有者と共有範囲を明確にし、特定の状態管理方式やViewModelの導入はアーキテクチャ設計で判断する。

## データ契約

Swiftの型例または表を使い、型名、フィールド、必須性、許容値、初期値、制約を定義する。Optionalでは欠損の意味も記述する。

```swift
enum ItemStatus {
    case idle
    case active
    case complete
}

struct Item {
    let id: String
    var label: String
    var status: ItemStatus
}
```

この例の型や初期値を一律に採用せず、PRDが要求する契約だけを定義する。

## フローと状態

- 主な利用者フローを順序付き手順またはsequence diagramで示す。
- 状態ごとの入口、出口、遷移条件、無効入力を示す。
- 初期、空、読み込み、成功、失敗、再試行、利用不可を必要に応じて扱う。
- 非同期処理の重複実行、キャンセル、画面離脱時の後処理、古い結果の反映防止を定義する。
- iOSの権限拒否、APIや端末機能の利用不可時に利用者が取れる操作を定義する。

## テスト観点

- 規則の境界値・状態遷移とサービスの契約を単体・統合テスト候補にする。
- 主要な利用者操作と表示変化をUIテスト候補にする。
- 既存構成がある場合、単体・統合は採用済みのSwift TestingまたはXCTest、UIはXCTestと対応させる。未採用の方式は確定事項にしない。
- 端末機能とレイアウトは必要に応じてSimulatorまたは実機で確認する。
- 確認できたproject/workspace、scheme、destination、test target等を記録し、未作成・未確認を区別する。このSkillではテスト観点の定義に留め、ビルド・テストは実行しない。

## 完成チェック

- PRDの各P0要件が設計とテスト観点へ対応している。
- 画面と端末API、状態遷移と純粋ロジックの責務が混ざっていない。
- 正常系だけでなく失敗・再試行・無効入力が定義されている。
- 実装者が未決事項と確定事項を区別できる。
