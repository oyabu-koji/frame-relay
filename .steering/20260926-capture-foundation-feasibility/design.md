## 設計概要・比較の順序

既存アーキテクチャの「表示→Application→純粋規則／I/O契約、Platformが契約を実装」の境界を小さく使う。今回不要な通信・削除・AF／ND等の実装や空ディレクトリを先行生成しない。コードの設計パターンや新targetを追加するための作業は置かない。

具体方式は、P04の資料・SDK契約比較→P05/P06の限定した探索実装→P07の実機／実ファイル比較→採用候補と残制約の記録→P08以降の検証実装へ進む。実録画が必要な比較を方式確定前に行えるよう、探索用adapterを交換可能にする。探索成功はPRD達成ではなく、探索版の動画を後の版の証拠として流用するときは変更影響と再試験要否を記録する。

| 比較ID | 候補と観点 | 判断に必要な証拠・停止条件 |
| --- | --- | --- |
| D01 記録出力 | 高水準の動画出力／sampleデータ＋writer等の標準API候補。LT/422/Proxy、実Log、4K24/30、補正、手動値、録画中切替、音声監視、開始終端、負荷を比較 | 使用SDKの契約＋同条件の実機保存動画。最初／最後の記録フレームや音声書込が取得できる範囲を明記。一方式の失敗で端末全体非対応にしない |
| D02 Log・表示 | 実際に列挙・適用できるLog種別ごとに入力色特性、標準Rec.709変換の由来と表示経路を比較。Core Image／Metal等は候補 | 標準変換の根拠、入力との適合、二重変換なし、原本非焼込み、描画・記録負荷。名称やメタデータ変更だけで成立にしない。由来不明なら品質保留 |
| D03 カメラ・補正・ズーム | 発見した物理／論理カメラと経路、実補正候補、実カメラ観測、倍率制御、切替の前中後、限定ISO制御を比較 | カメラ数・可変絞り・複数同時カメラ利用を仮定しない。補正維持／記録継続を守れない経路を無通知で有効化しない |
| D04 保存証拠 | 操作・設定・原本参照を一つの永続storeへ保持する契約。Core Data＋SQLite第一案を、最小ファイルstore等と必要範囲で比較 | commit・期待世代・再起動読戻し・ファイルとの非原子的境界・障害の証拠。DB名で保証を置かず、選定はP07。診断ログだけの代替は禁止 |
| D05 観測・検査 | 標準APIによる媒体検査・再生と時刻対応。直接観測、callback、推定の粒度／計測負荷を比較 | 保存ファイルと設定の対応を失わないこと。取得不能なら未観測と影響を明示。外部解析ツール追加は前提にしない |

不成立・証拠不足が見つかったら、比較した方式、他候補へ影響する契約、追加確認と必要な要求判断を残す。標準LTを別形式へ黙示変更せず、代替試験は別のケースIDとする。必要な依存判断を解決できなければ該当タスクをblockedにし、独立した準備・観測だけを進める。

## 最小検証画面と所有する状態

検証専用のSwiftUI画面からケースID・希望条件を明示選択し、適用、REC/STOP、手動値、WB合わせ直し、補正、寄る／引く、目標／途中停止、レンズ切替を操作する。仮のフォーム・ボタン等の配置は実装時の試験操作であり製品UI採用ではない。初回fpsやISO等を隠れた既定値にせず、試験票の値を本人が選択する。

希望値／能力／実適用、撮影状態、音量／入力／到着／書込、保存結果、不可理由、ケースと動画参照を別表示にする。確認済み音声入力障害はメーター付近の赤い×＋理由等とし色だけに依存しない。保存動画1件を開いて映像・音声を確認する最小再生手段を持つが、FR-10の製品一覧やFR-13の軽量版確認状態は作らない。停止中の表示を実録画中として残さない。

| 状態 | 唯一の更新責務・寿命 | Viewへの共有 |
| --- | --- | --- |
| 希望設定・ケース選択 | 設定担当。本人入力と試験票から。前回選択は現在能力と再照合 | 希望値と適用成否を別snapshot。WB固定値は次クリップ設定に保存しない |
| 能力・実適用・設定世代 | 撮影調停担当。I/O事実で更新しセッション／設定世代を持つ | 未確認／非対応／適用失敗／確認値、観測時点を区別 |
| REC、WB、音声、ズーム・切替 | 撮影調停担当。画面より長いセッション寿命 | 主に値snapshot。sample本体やSDKオブジェクトをView状態へ流さない |
| 原本参照・保存操作・結果 | 保存担当と永続store。撮影IDごと、画面離脱後も維持 | 正常／部分／不明／失敗と照合の状態。UIキャッシュは正本にしない |
| ケース／反復／証跡・評価 | 検証記録担当。実施版・環境・ケースIDに対応 | 観測・品質・PRD達成を別軸。実施者の評価入力を自動合格にしない |
| 原本再生 | 再生担当。対象参照を固定し再生中使用権を保持 | 再生結果のみ。録画／保存／確認の状態を書き換えない |

## モデルとI/O契約

以下は責務と必要な値契約であり、Swift型名・schema・具体クラスの固定ではない。欠損値には未取得、API取得不能、非対応等の理由を持たせる。独立した事実を一つの`isComplete`へ潰さない。

| 契約／責務 | 入力 | 出力・不変条件 |
| --- | --- | --- |
| 撮影能力照会 | 環境ID、カメラ候補、希望組合せ | カメラID・物理／論理対応、形式・色特性・fps範囲、絞り制御有無、補正候補と制約。照会成功≠適用≠録画≠品質 |
| 設定適用 | セッションID、操作ID、期待設定世代、希望値 | 適用完了事実、読戻した実値・時点・取得不能理由。無断代替を返さない |
| 記録・WB・ズーム | 撮影ID、REC/STOP、本人操作、試験条件版 | 受付・開始／終端・設定適用・実カメラ／倍率・エラーの型付きevent。callbackに元操作と世代を対応 |
| 音声観測 | 入力経路、到着・書込経路の事実 | レベル、入力確認状態、sample到着の時点／範囲、書込受付／完了／失敗。静寂、音割れ、不達、書込失敗を独立に保持 |
| 固定表示 | 識別済Log入力・色特性・表示条件版 | 固定Rec.709表示面、描画時刻・負荷。記録へ逆流させずLUT選択／自動味付けなし |
| 原本保存・検査 | 撮影ID、アプリ管理領域の不透明参照、記録結果 | ファイル確定、映像／音声track・形式・サイズ・時間・色特性・再生検査、部分／不明／失敗。任意パス／外部削除を受理しない |
| 永続store | 操作意図、対象参照、期待世代、結果と検査事実 | 永続storeまでのcommit結果と再起動読戻し。古い／二重commit拒否、媒体との一括原子性は仮定しない |
| 復旧 | 未完了操作、実ファイルへのアクセス・検査結果 | 照合済み結果と不可理由。ファイル存在のみで正常保存にしない。結果不明は維持 |
| 観測記録 | ケースID、試行ID、時刻、設定／操作／結果 | 最小限の診断eventと、復旧用永続記録とは別の評価証跡。媒体本体や秘密を含めない |

識別は `環境ID → 試験票版 → 組合せID → ケースID → 反復ID → 撮影ID → 原本参照／設定世代／保存操作ID → 証拠ID` を辿れる形にする。二本連続のC05は同一ケースに別撮影IDを二つ持たせ、意図的中断と再実行を別反復にする。

## 非同期処理・RECと記録フレームの境界

UI更新はMainActorへ限定する。カメラ構成・開始停止・設定は専用の直列領域、映像／音声処理とwriterはAPI所定の領域、媒体検査・storeはそれぞれのI/O領域を所有する。SDKオブジェクトの無条件なactor間転送や、警告隠しの隔離解除を前提にしない。既存MainActor既定と言語モードでコンパイル診断する。

`preparing → ready → starting → recording → stopping/finalizing → preparing/ready` は撮影セッションの状態。撮影ごとの保存結果は独立して `recording → finalizing → saved/partial/unknown/failed` を保つ。次RECの可否はカメラ・音声・記録先・必要I/O資源で判定し、前クリップのサムネイルや表示更新だけを待ち条件にしない。同時保存が安全と未確認なら理由付き準備中を示し、性能計測のために安全な確定を省略しない。

1. 待機中WB Autoから、REC受付時に取得できるWB値と時刻を記録して固定要求を発行する。安定待ちやND完了待ちは加えない。
2. REC受付、WB固定要求／適用確認、実記録開始、最初の記録映像／音声sampleを別の事実として記録する。UIイベントやdelegate通知の時刻を最初の保存フレームと同一にしない。
3. 本人の合わせ直しは操作IDを付け、更新区間と再固定の値／時点を記録する。ISO・絞り・シャッターを維持する。別の設定操作・STOPと競合した場合の順序を一つの調停経路で決め、古い完了を現状態へ反映しない。
4. STOP／確認済み障害で終端へ進み、最後に記録されたフレームの境界までWB固定を維持する。停止受付で即Autoへ戻さない。記録終端が確認できてから待機Autoへ戻し、次クリップは新しい値を取得する。
5. 出力方式がフレーム境界や音声書込を直接公開しない場合、媒体PTS等との照合方法・callbackによる推定・時間分解能・誤差／取得不能を明記する。直接観測と推定を混ぜず、境界を証明できない条件は証拠不足のまま。観測方式の改善をC18へ戻す。

媒体PTS・単調時刻・実施日時を別に保持し、時計間の対応と分解能を試験票へ記す。壁時計だけでフレーム順序を断定しない。REC連打・STOP重複は操作IDで一つの記録へ集約し、`await`付きactorだけで操作全体の排他が完成したとしない。画面離脱やtask取消しは記録停止・保存成功の証拠ではなく、実停止・保存結果を待って照合する。

## 音声・保存・エラー処理

入力有効性は `checking/valid/failed/recovering` 等、レベル値、sample到着、writer結果は別状態とする。低音量・ゼロだけでfailedにしない。確認済み障害はREC前なら開始抑止、録画中なら停止し保存可能部分を確定する。有限な試験用猶予・再試行回数・対象範囲はG02で束縛して試験版に記録し、製品の既定値にはしない。復旧成功はreadyへの復帰であり、自動RECではない。

保存は撮影ID・管理領域参照・操作意図を先に永続化し、記録終了→ファイル確定→検査→結果commitを別観測にする。正常保存には対象対応、writer終端、必要な映像／音声を含む検査結果と記録の一致が必要。救済できた正常区間は部分保存として区別し、何が失われたか不明ならunknownを保持する。参照不可をファイル消失にしない。

復帰・再起動は未完了操作と実媒体を照合し、最後のUIがrecordingでも録画中へ復元しない。正常／部分／不明／失敗の理由、復旧状態、次に可能な操作を分ける。診断ログ欠落でも必要な復旧証拠をstoreに保持する。store破損を空store生成で成功扱いにせず、原本自動削除・アプリ全体自動再起動をしない。

| 条件 | 処理・観測 | 停止／保留の範囲 |
| --- | --- | --- |
| 権限拒否、入力／記録先未準備 | 原因と設定変更等の手段を表示、該当条件を準備中／不可 | 記録に必要ならREC不可。ND警告等とは分離 |
| 組合せ非対応／適用失敗 | 希望・実値・理由を保持、別設定は本人選択による別ケース | 当該適用と依存録画。元要求を達成にしない |
| 音声入力／書込障害 | 確認事実と段階を記録、開始抑止／停止・部分確定を試行 | 音声なしの継続をしない。復旧結果と保存結果を別管理 |
| 補正を維持できない切替 | 実行前に拒否／制約を示し、現在の記録を優先 | 当該切替。別補正への無通知変更なし |
| 容量・熱・負荷 | 実値と制約・影響を記録、記録不能なら停止と保存結果照合 | 未合意の閾値・自動負荷削減を製品動作にしない |
| 中断・store失敗・証拠欠損 | 最終確定段階と実媒体を照合、unknownを保持 | 必要な依存処理を止め、部分救済を保証しない |

## ケースの母集団と実行票の展開

ケース数を端末名から固定しない。P07で実値を取得した後、P17前に次の規則で全件の実行票を作り、tasklist内の母集団台帳に件数と版を記録する。失敗後も行は削除しない。

1. **カメラ集合 C**: 実機で発見した撮影に利用し得る全カメラ。物理カメラと論理／複合カメラの対応を併記し、同一視せず各経路を識別する。照会できない候補は未確認行を残す。
2. **基本形式**: `C × {4K} × {24,30fps} × {ProRes 422 LT, 422, 422 Proxy}`。4KはAPIの実解像度を記録してPRD意図と照合する。非対応セルを別解像度・fpsへ置換しない。
3. **Log集合 L(c,format)**: 発見・照会した実Log種別を全て候補として対応付ける。種別不明／候補なしも行と根拠を残す。Log 1/2等の名称を機種名から決めず、今回の採用比較と対応表を分ける。
4. **補正集合 S(c,format,log)**: OFFと、照会できた実モードを全て候補として対応付ける。組合せによって非対応でも消さず理由を記す。複数の程度／特性が成立しないならFR-03の未達を残し、架空のモードを作らない。
5. 完全な組合せキーを `cameraID / width×height / fps / codec / actualLog / stabilizationCandidate / outputCandidate` とする。能力、適用、実録画、保存、品質は別列。出力候補の比較が終わっても比較元の失敗行を保持する。
6. C02は全セルの実行可否を扱う。実行可能な全セルにC03の適用・音声付き録画・保存検査を割り当てる。`LT＋Log`の実行可能な全セルを標準集合Bとし、C16の同時成立を24/30・各カメラ・各Log・OFF／実補正別に実行する。標準が不能なら代替セルの成功をBの成功へ転用しない。
7. 機能単独の基準集合B0は、Bの各カメラ×各fps×各LogについてOFFを選ぶ。OFF自体が実行不能なら行を残し、比較用の他モードは本人が別票で選ぶ。C04〜C08/C11/C13の基準はB0、C09/C10はB全補正。codec・出力・Log・カメラ・fpsで契約／実挙動差があれば、その差を持つLT以外のセルも各ケースへ追加する。理由のない代表一件への縮約をしない。
8. レンズ移行集合Eは、実際のカメラ／経路と希望形式・補正で調べた有向移行（往路と復路を別）とする。C12/C16は対応が確認できた全Eと、確認済み非対応Eでの無通知実行抑止を扱う。中間倍率と実カメラの対応も記録する。該当経路なしをケース削除で隠さない。

全実行票は `群ID-組合せID-条件版-反復ID` で識別し、少なくともCF、AC-CF、PRD AC、依存セル、手順、期待観測、必須証拠、試験パラメータ、実施状況を持つ。ケースの具体媒体・値はrepo外の証跡台帳で管理し、tasklistへ匿名IDと件数・結果を同期する。

### 比較・反復の共通規則

- G02で各ケースの値を**実施前**に束縛する。シーンID（照明・被写体・距離・動き・端末向き）、手動値、開始／目標倍率、試験速度、途中停止時点、クリップ長、比較順、反復数、冷却／再準備条件、判定方法を空欄のまま実行しない。製品未決値には「探索用・製品未採用」と記す。
- 基準と比較条件は同じシーン・手動設定・音声源・クリップ長・実装版で、原則一要因だけ変える。補正はOFF→候補→OFF、表示は記録単独→表示併用→記録単独、ズーム／切替は静止記録→操作あり→静止記録を一組の比較とし、前後の基準で環境ドリフトを確認する。相違が不可避なら値と影響を記録し品質比較を保留する。
- 反復は試験票に確定した有限回数で全結果を残す。回数は資源・観測分解能・評価方法からP03/P07で決め、成功するまで無限反復しない。同じ条件の独立した再準備からの再実施を含め、失敗・中断を分母や母集団から除かない。品質合格用の回数・許容範囲は本人との事前合意が必要。
- C05の「二本」はWBの要求そのもの。C16/C17は約30秒と2〜3分内で選んだ実時間、二本以上の連続撮影を含む。有限の本数と各長さは実空き容量・安全な試験範囲を踏まえて事前に記録する。全体の製品録画上限にはしない。
- 探索の許容未合意は`品質: 許容範囲未合意`として観測値だけを残す。後から閾値を測定結果に合わせて作り合格へ昇格しない。品質試験は合意した条件版で実施する。

| 境界 | 中断を挿入する位置 | 照合する事実 |
| --- | --- | --- |
| B1 | 撮影意図／出力参照のcommit前・後、実記録開始前 | 受付だけの操作、ファイルなし／未完成を成功にしない |

P03/P07で各境界の実到達を示すhook／eventと中断方法を定義し、実装の単なる行位置と製品上の境界を混同しない。Port注入（規則・順序）、使い捨てdisk／プロセス再起動（永続性）、実OSイベント（実機I/O）を別票にする。実OSで任意の瞬間に再現できない境界は、到達証拠が取れた試行だけをその境界の実施とし、未到達・未整備を残す。

権限試験はOS設定から可能な範囲を確認し、設定変更の対象を記録する。アプリ削除や既存媒体の消去を初回状態作成に使わない。容量・書込障害は注入や隔離した使い捨て領域で再現し、実端末を埋め尽くさない。実容量・熱の挙動は許可された通常の撮影で観測した範囲を記録し、未観測の極限状態は未確認とする。必須の実機障害を代替だけで閉じられない場合は工程の残件として扱う。

## 証跡の保存と分類

アプリ内の新規検証原本はアプリ管理領域へ置き、削除・写真追加・送信を検証画面の通常経路に持たせない。試験媒体の外部保管が必要なら、P03で本人管理の**repo外ローカル保管先**を決め、必要な参照／複製の対象と方法を確認する。場所が未確認の現在はパスを創作しない。外部クラウドやMediaVaultへの転送を前提にしない。

保管先を不透明な`vaultID`で参照し、内部を `runID/caseID/repetitionID/clipID` の階層で対応付ける計画とする。実媒体、私的な対応表、無加工の動画・音声を含む診断資料はその保管先だけ。repoのtasklistには匿名ID、相対的な証拠キー、件数、非機微の環境値・観測・判定だけを置く。完全な私的パス／URL、顔・音声、端末固有の秘密識別子は記さない。削除／保管期限は本人との別合意まで未決とし、勝手に整理しない。

各実行票に実施日時・実施者、実装版（commitに加えて未commit差分の識別）、環境・条件版、希望／能力／実値、原本参照、媒体検査、操作／REC／フレーム／音声／終端／commit時刻、ログ・管理記録の照合、品質合意IDと項目別判定を持たせる。ケースと動画が対応不明なら証拠欠損とする。動画の再エンコード・内容変更を行わず、複製が必要な場合の同一性確認法はD05で選ぶ。MediaVaultの全内容検証要件達成とは別の対応確認である。

| 独立した軸 | 値・扱い |
| --- | --- |
| 実施 | 未実施／実施済み／中断／前提条件により実施不能。環境不足・手段未整備は未実施理由とblockedを残す |
| 動作観測 | 成立を観測／条件付き成立／不成立を観測／判定保留。直接・推定・取得不能の粒度を併記 |
| 原因 | 仕様上の非対応／実装上の問題／原因未確認。比較根拠がないなら原因未確認 |
| 品質 | 許容範囲未合意／未測定／適合／不適合を評価項目ごとに記録 |
| PRD | 未評価／未達／受入条件を満たした判定。部分観測は全条件達成へ昇格しない |
| 工程 | AC-CFごとの未実施／継続／完了と根拠。task完了とも別に管理 |

## 実装順と引継ぎ

P01〜P04で前提と比較・試験票を用意し、P05〜P07で最小探索と方式判断、P08〜P14で検証画面・保存・WB・音声・表示・補正・ズーム、P15〜P16で境界テスト・build・起動、P17の単独→P18の統合／性能→P19の故障／中断→P20の切り分け→P21の全P0照合へ進む。障害は発見時点でもC18へ回し、後の試験の安全な前提を満たしてから続ける。

方式・制約・製品合意が安定文書を変える場合、P21で関連docsの更新要否と根拠を整理し、実装Workflowの所有範囲を明示した文書担当へ同期する。今回の計画ではdocsを変更しない。実装検証は別の明示 `$validate-implementation` へ同じsteeringを渡し、専門agentによるread-only検証とする。本書作成をその検証開始の許可にしない。
