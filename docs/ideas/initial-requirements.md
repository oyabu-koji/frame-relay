## Project Overview

- Project name: FrameRelay
- One-sentence summary: iPhone 18 Proで家族・旅行の高品質動画を撮影し、原本をMac miniへ安全に転送して、Rec.709軽量版の確認・「写真」への保存と端末原本の整理まで行う個人用iOSアプリ。
- Problem to solve: 撮影中の露出・ピント・WB・音声・ズームの失敗を抑え、容量の大きい原本をiPhoneから安全に片付けつつ、日常的に見返せる軽量版を残したい。

## Users

- Primary users: iPhone 18 ProとMac miniを使う本人。家族・旅行の撮影者であり、転送・確認・削除を判断する人。
- Usage context: 外出先で家族や景色を撮影し、Wi-Fi接続時に手動でMac miniへ転送する。Mac miniのプレビューを確認した後、iPhone容量を整理し、必要な軽量版を「写真」に手動保存する。

## Product Goals

- 撮影者の設定を尊重し、撮り逃しや意図しない露出・WB・ピント・音声の変化を減らす。
- 改変しないLog原本をMac miniに保存・検証し、見返しやすいRec.709軽量版を生成する。
- 明示的なプレビュー確認と状態記録に基づいてiPhone原本を安全に手動削除し、同じ軽量版の重複保存を避ける。

## In Scope

- 録画、固定の標準Rec.709撮影プレビュー、OFFと複数モードを選べる手ブレ補正、WB、音声レベルと入力障害への対応、理由付きND案内、人物選択と主役追跡、滑らかなズーム・構図予告・停止支援、レンズ切替、アプリ内原本保存・一覧・再生を初期版に含める。
- Wi-Fi時の手動原本転送、Mac miniでの原本保存・整合性検証とRec.709軽量版の自動生成、FrameRelayでの軽量プレビュー再生と明示確認、確認後の手動原本削除を初期版に含める。動画本体を送受信する処理は、軽量プレビューのストリーミング・一時取得も含めWi-Fi接続時に限定する。
- Wi-Fi時に手動で軽量版を「写真」へ保存する。既存MediaVaultの動画は開発中の実データ試験に使用する。

- 初期版でのLUT選択・既存動画の一括再変換。将来変更できる余地は残す。

## Acceptance Criteria

- iPhone 18 Proで標準の4K・24fpsまたは30fps・ProRes 422 LT＋Apple Logを選んで録画すると、実機でその組合せが対応する場合は音声付き原本がFrameRelay内に保存され、「写真」へ同じ原本が追加されない。非対応の場合は黙って別形式・レンズ機能へ切り替えず、制約と代替案を提示し、標準要件の見直しが必要であることを示す。
- 撮影待機中・録画中に、固定の標準変換によるRec.709撮影プレビューを利用できる。表示用の変換をLog原本へ焼き込まず、この表示を見ただけでは削除前の軽量プレビュー確認済みにならない。LUT選択UIは初期版の条件にしない。
- 撮影待機中に手ブレ補正をOFFまたは程度・特性の異なる複数の補正モードから選べる。現在のカメラ・録画形式等で使えるモードを区別し、非対応なら制約を示してユーザーがOFFか対応モードを選ぶ。初回は標準相当を第一候補とし、以後は対応する撮影条件で前回の選択設定を復元する。録画中の手動切替は必須にせず、アプリ判断で補正モードや強さを勝手に変えない。OFFだけでは要件達成とせず、標準の録画条件で希望する補正が成立しなければ制約・代替案を示し、必要に応じて要求を再確認する。
- 選択した手ブレ補正が実際に適用され、保存されたLog動画で補正効果、構図、音声同期、録画継続性を確認できる。補正のために録画形式や手動シャッター・ISO・WBの方針を無断で変更しない。補正による撮影範囲の変化を撮影プレビュー・構図予告・ズーム停止支援へ反映して検証し、ズームやレンズ切替で選択補正を維持できない場合は、その切替を無通知で実行しない。
- 撮影待機中のWB AutoからRECを押すと、その時点のWBが録画中に固定される。録画中の合わせ直しはユーザー操作時だけ行われ、録画停止後は次の撮影に向けてAutoへ戻る。
- ND案内を利用すると、選んだ撮影意図に対して濃くする・薄くする等の方向と判断理由が示される。撮影者と合意した評価可能な代表条件では有用な方向・理由が一致し、評価困難な条件では判定を保留できることをともに確認する。常に判定不能となるだけでは合格にしない。根拠が足りない場合は確定した調整量を装わず、解析停止・遅延時に古い結果を現在のOKとして残さない。
- 人物を主役に選んで録画中に見失うと、数秒間ピントを保ち、同じ人物を再捕捉した場合は追跡へ戻る。戻らない場合は別人へ自動で移らず、控えめな状態表示とタップによる再指定が可能になる。
- 目標倍率を選んで構図予告を表示すると、撮影前に到達先の構図の目安を見られる。予告を見るだけでは録画倍率は変わらず、予告表示は原本に記録されない。録画中はゆっくりズームして目標で停止でき、途中停止もできる。レンズ切替時は適用中のカメラ・撮影条件を正しく示し、非対応の組合せは黙って切り替えない。
- ND判定や人物検出が完了していなくても録画でき、結果が不確かな場合は古い判定を現在の確定結果として示さない。確認済みの音声入力障害では無音録画を続けず、正常に撮れた部分を可能な限り保存する。
- Wi-Fi接続時に一覧から原本転送を手動開始すると、Mac miniで原本の保存・整合性検証後にRec.709軽量版の生成が自動で始まる。完成した軽量版は元のフレームレート、縦横の向き・構図、音声、撮影日時を維持し、Apple LogからRec.709への変換結果が確認できる。Wi-Fiが切れた場合、モバイル回線で転送を続けない。
- Rec.709変換済みの軽量プレビューを再生してユーザーが明示的に確認すると、全編再生を条件とせず確認済みを記録する。同一の撮影原本に対する保存・整合性検証と、ユーザーが確認した同一の軽量プレビュー映像の記録が有効なら、Mac miniへ再接続せずにiPhone原本を手動削除できる。再変換による新版の生成は可能だが、確認済み版の差し替えは、対象端末が旧確認の失効を認識して永続保存したと確認してから確定する。失効保存前に端末がオフラインなら差し替えを保留し、その間は旧版の有効な記録に基づく削除を許可する。失効保存後は通信切断や差し替えの保留で旧確認を有効に戻さず、新版の明示再確認まで削除できない。単なる再ダウンロードや確認後のWi-Fi切断では確認を失効させない。未変換Apple Logプレビューの確認や既存バックエンドの削除候補状態だけでは削除できず、いずれかの記録または対応関係が不明・失敗でも削除できない。自動削除もしない。
- オフライン削除は最後に取得した保存・検証の記録に基づく。削除時点のMac mini原本の存在を再確認した扱いにはせず、オフライン中の原本消失など端末が未取得の変化を削除時に検知できないことを許容する。
- Wi-Fi接続時に軽量版の「写真」への保存を手動開始すると、成功時に「写真」から再生できる。同じ変換版を繰り返し操作しても無条件に重複追加せず、Wi-Fiが切れた場合はモバイル回線で取得を続けない。
- 原本転送・軽量版ダウンロード・軽量プレビューのストリーミング／一時取得はWi-Fi接続時だけ行い、Wi-Fiが切れた場合は待機する。取得済みのローカル動画はこの制限を受けず再生できる。RECで中断した動画通信は、録画・保存終了後もWi-Fi接続やユーザーの停止状態等の条件を再確認し、条件を満たす既開始の処理だけ再開する。
- 保存・検証・明示確認・「写真」登録の処理境界で中断・再起動しても、正常保存、部分保存、結果不明、失敗を取り違えない。HTTP送信完了だけで検証済みにせず、同一原本・同一軽量プレビューへの確認記録の確定を区別し、「写真」への保存結果が不明なら無条件に再追加しない。ファイル救済の成功そのものは保証しない。
- 開発中はMac miniにある既存MediaVault動画の原本でRec.709変換・プレビューを確認し、FrameRelayからMac miniへの原本転送はFrameRelayで新規撮影した動画で確認する。旧「写真」原本の削除や汎用移行をその試験の前提にしない。

## 2. アプリの目的と利用場面

### 2.1 目的【確定】

FrameRelayは完全に自分用のiPhone動画撮影・管理・Mac mini転送アプリとする。

高品質な家族・旅行動画を残す際に、撮影者が決めた撮影条件を尊重しながら、ND調整、人物と背景の露出確認、ピント合わせ、ズーム、保存・転送を支援する。

多機能な汎用プロカメラアプリの全機能を再現することは目的ではない。気軽な撮影は純正カメラを使い、FrameRelayは高画質で残したい撮影に使う。

### 2.2 主な場面【確定】

| 項目 | 内容 |
|---|---|
| 主な被写体 | 子ども＋街、子ども＋自然、妻＋街、妻＋自然 |
| その他の構図 | 人物の顔アップ、人物がいない景色 |
| クリップの長さ | 通常30秒程度。時々2〜3分。これは使用傾向であり、録画時間の上限ではない |
| 最優先で避けたいこと | 録画失敗、子どもの撮り逃し、意図しない露出やWBの変化 |
| 起動目標 | 保存済み設定を使い、詳細設定をしない場合は起動から2〜3秒で撮影可能にしたい |

起動時間は目標であり、未検証の達成保証ではない。初回権限取得、通常の起動、復帰などの条件を分けて測定する。

## 3. 対象範囲と技術方針

### 3.1 アプリとサーバー【方針合意】

iPhone側はSwift／SwiftUIを中心とするネイティブアプリへ移行する方向。カメラ機能はAVFoundationなどの対応するAppleの仕組みを調査して構成する。

Mac mini側までSwiftへ書き換える要求はない。現在のバックエンドの言語、API、認証、保存構成、通信経路、実装済みの機能は、ソースや既存仕様を読んでから判断する。

### 3.2 この文書とAI開発テンプレートの境界

この文書は「何を作るか」を記録する。AI開発テンプレートのルール、ビルド・テストコマンド、承認手順、ファイル配置は別に整備する。

## 4. 撮影の基本設定

### 4.1 標準と手動操作【確定】

| 項目 | 要求 |
|---|---|
| 解像度 | 基本4K |
| フレームレート | 主に24fpsまたは30fps。ハイスピード撮影は主要用途ではない |
| シャッター | 撮影者の指定を維持。基本案は180°。露出合わせのために勝手に変更しない |
| ISO | ユーザーが値を設定し、通常は固定。特定の最低値を強制しない |
| 絞り | 対応するカメラではユーザーが自由に設定。常に特定のF値へ固定する仕様にしない |
| 使用レンズ・倍率 | ユーザーが選ぶ。録画中のゆっくりしたズームを重視 |
| 露出調整 | シャッター・ISO・絞りを決めたうえで、物理NDフィルターをユーザーが調整する |
| WB | 待機中Auto、REC時点で固定。詳細は第5節 |
| 手ブレ補正 | OFFと程度・特性の異なる複数モードから撮影待機中に選択。初回は標準相当を第一候補とし、以後は対応する撮影条件で前回の選択設定を復元。詳細は第18.1.1節 |
| 初期状態 | 保存済みの設定を使って、詳細設定をしなくても撮影できるようにする |

NDの操作はユーザーが行う。アプリが物理フィルターを回せる、現在の濃度や最小・最大位置を自動取得できる、とは前提にしない。

ISOや絞りの変更で露出が変わった場合は、その条件でNDの案内を再評価する。アプリが勝手に別の設定へ戻して帳尻を合わせない。

### 4.2 絞りとLens Match【方針合意／要技術検証】

絞りは露出と表現のために使えるようにする。レンズ間の共通絞りに揃えるLens Matchは、その中の補助機能として扱う。

複数のカメラで同じ絞り値が実際に使える場合、対応する値へ合わせる操作を検討する。会話に出たf/2.8などは、端末の対応確認なしに固定要件へしない。

同じF値でも映像の明るさ・色・ピントが完全一致することは要求の前提にせず、レンズ切替全体として検証する。非対応カメラに操作可能な絞りUIを表示しない。

### 4.3 撮影プレビューの色表示【確定／要技術検証】

初期版では撮影待機中・録画中の映像を、撮影するLog形式に対応する固定の標準Rec.709変換で表示できるようにする。表示用の変換をLog原本へ焼き込まず、原本の記録形式を維持する。撮影プレビューを見たことを、Mac miniで生成した軽量プレビューの明示確認に代用しない。

LUT選択UIは初期版の対象外。表示処理、表示切替の操作、描画性能と録画への影響は後続の設計・実機検証で決める。固定の標準表示が成立しない場合も、未変換表示だけでこの要件を達成した扱いにはしない。

## 5. ホワイトバランス【確定】

### 5.1 状態遷移

| タイミング | 要求する動作 |
|---|---|
| 起動・撮影待機中 | WB Auto。ND調整中もAuto |
| REC操作 | その時点で取得できているWBを固定。WBの安定待ちを理由に録画開始を待たせない |
| 録画中 | 固定を維持。アプリ判断でAutoへ戻さない |
| 録画中の「WBを合わせ直す」 | ユーザーが押した場合だけ現在の光に合わせ直し、その後再固定 |
| 録画停止 | 最後の記録フレームまでは固定し、その後Autoに戻る |
| 次のクリップ | 新しくAutoで測定して開始。クリップ間の微妙なWB差は許容する |

「このWBを保持」など、次のクリップにも固定値を引き継ぐ機能・モードは不要。後から標準機能として復活させない。

「WBを合わせ直す」はISO・絞り・シャッターを変更する操作にしない。録画中のWB再測定と更新が不自然な色変化や録画停止を起こさないかは要検証。

### 5.2 ND案内との関係

ND判定が完了したら自動的にWBを固定する、という手順は採用しない。WBを固定する通常のきっかけはREC操作とする。

待機中の露出評価はWBが変化し得る状態での案内として扱い、固定後も確認を継続する。RGBヒストグラムを中央に揃えることや、RGBを同じ分布にすることをWB調整の目標にはしない。

## 6. 人物選択・ピント・背景

### 6.1 撮影意図【確定】

撮影意図は「人物のみ／人物＋背景／景色優先」を基本とする。人物だけでなく、旅行先の景色や街の雰囲気も残したい。

「人物＋背景」は背景にも必ずピントを合わせるという意味ではない。背景のボケと、背景の明るさ・色・階調を大切にすることを分ける。

### 6.2 人物とフォーカス【方針合意】

人物を自動検出して候補を表示し、タップで選べるようにする。複数人を選べるが、ピントの主役は一人指定する。

| 用途 | 方針 |
|---|---|
| 複数人を残したい | 選んだ複数人の露出を評価する |
| 主役を指定して追跡 | 一人の主役を優先してピントを合わせ続けることを目指す |
| 特定の人を追跡しない | 人物優先のAFを使いたい。追跡OFFをピント固定と同義にしない |
| 人物なし | 風景撮影に対応。対象の指定やAF動作の詳細は未決 |

露出の対象選択とピントの主役は分けて管理する。選んだ全員へ、距離に関係なく同時にピントを合わせられると約束しない。

主役を見失った場合は数秒間ピントを保持し、その間に同じ主役を再捕捉できれば追跡に戻る。戻らなければ別人へ自動で移らず、ピントを保持して控えめに状態を示し、画面タップで主役を再指定できるようにする。秒数、表示方法、手動フォーカスの詳細は実機検証とUI設計で決める。

### 6.3 背景ぼかし【候補・要技術検証】

自然なボケと、画像処理で追加するボケを区別する。画像処理による背景ぼかしも検討対象として残すが、通常の撮影の成立条件にはしない。

Appleのシネマティック系機能の利用可能性を調査し、ProRes 422 LT＋Apple Log、4K、手動露出、録画中ズームとの両立を確認する。対応APIの存在だけで全条件の同時利用が可能とはしない。

両立できない場合は別モード化または後回しを検討する。仮想絞りの値を物理絞りと同じ設定として扱わない。普通に撮影したLog原本に必要な奥行き等の情報が自動的にあるとは想定しない。

## 7. ND調整・露出ガイド

### 7.1 中心価値【確定】

単なるOK／NGより、「人物は適切、背景の一部が明るすぎる、NDを少し濃く」など、理由を含めた案内を行う。

必要な根拠が得られる場合は調整量の目安も示したい。ただし、NDを何段調整すべきかを必ず正確に算出できることは未検証であり、条件を満たさない場合は無理に数値を出さない。

評価対象は、選んだ人物、重視する背景、ハイライト、暗部、必要に応じたRGBチャンネルの状態。小さな光源や反射、元々黒いものが存在することだけでNGにしない。

撮影者と合意した評価可能な代表条件では役に立つ方向・理由を示し、評価困難な条件では保留できることの両方を確認する。常に判定不能となるだけでは要求を満たさない。代表条件と評価方法は実機評価に向けて合意し、数値の閾値や内部アルゴリズムはこの段階で固定しない。受入例は第20.2節に示す。

### 7.2 判定の表現【方針合意／詳細未定】

| 表示の意味 | 動作・注意 |
|---|---|
| NDを濃くする方向 | 撮影意図を前提に、露出を下げる操作を案内 |
| NDを薄くする方向 | 撮影意図を前提に、露出を上げる操作を案内 |
| 現在の基準では許容範囲 | 絶対的な画質保証ではなく、設定した評価条件を満たしていることを示す |
| 人物と背景の両立が難しい可能性 | NDだけでの調整が難しいことを案内。構図・光・優先対象の変更を提案 |
| 判定中・未確認・根拠不足 | 正直に表示。誤ったOKや精密そうな数値で埋めない |

会話中の「SCENE RANGE TOO WIDE」は、撮影したい明暗の両立が難しい状態を伝えるための呼称。白・黒のピクセル数だけでシーンの記録可能性を断定するアルゴリズムにはしない。

0 EV、ヒストグラムの中央、100 IRE、固定のクリップ率を普遍的な正解として使わない。記録側の情報とLUT表示側の見え方を区別する。飽和などで失われた情報から正確な余裕量を必ず逆算できるとは想定しない。

### 7.3 録画可能と露出評価は分ける【方針合意】

ND判定や人物検出の完了を録画開始の必須条件にしない。露出の警告があっても、撮影者の判断で録画できるようにする。

ただし、権限がない、記録先が使えない、音声入力の異常が確認されているなど、必要な記録条件を満たさない状態は別問題として扱う。「露出OK」と「音声を含めて録画可能」を一つのチェックにまとめない。音声異常の扱いは第16節に定める。

## 8. ズーム・構図予告・停止支援

### 8.1 ユーザーの希望【確定】

録画中は、倍率を瞬間的に切り替えるだけでなく、ゆっくり寄る・引く操作を重視する。

2倍・4倍・8倍などの数字だけでは移動後の構図が分かりにくいため、事前に構図を確認できる表示、または途中で停止できる操作が必要。

途中停止では可能な範囲で引き伸ばしを避けたい。4倍を狙っているときには、その付近で正確に止めやすくしたい。

### 8.2 構図予告【方針合意／詳細未定】

ズーム先の撮影範囲を枠で表示し、必要なら小窓で拡大プレビューを表示する案を採用候補にする。予告だけでは実際の録画倍率を変更せず、枠や小窓を記録に焼き込まない。

現在の映像を切り出した予告は、構図の目安として扱う。別カメラでの画質・ボケ・位置関係まで完全再現したプレビューとは表示しない。

広い画角へ戻す予告に別カメラ取得が必要な場合、対応条件と負荷を検証する。予告表示が録画の安定性を損なう構成は採用しない。

### 8.3 操作案【方針合意／詳細未定】

目標倍率を選択し、予告を見た後、ゆっくりズームして目標で自動停止する。途中停止もできるようにする。

押している間ズームするか、開始操作後に自動移動するか、スライダーを併用するかなど、具体的な操作方法はまだ最終確定していない。

| 停止時の条件 | 現在の提案 |
|---|---|
| 引き伸ばしなしで利用できる範囲 | その位置に停止できる |
| 適した停止候補の近く | ごく小さな滑らかな補正で候補へ合わせる |
| 目標倍率へ到達 | 目標を超えず停止する |
| 近くに適した候補がない | 構図を守って即停止するか、画質を優先して候補へ移動するかは未決 |

近傍への吸着量、速度、停止までの遅延、触覚フィードバック、録画中と待機中の違いはこれから決める。

### 8.4 画質の扱い【要技術検証】

整数倍率なら高画質、小数倍率なら低画質とは判定しない。実際のカメラ、撮影フォーマット、出力解像度、ズームの状態を確認して推奨停止位置・範囲を決める。

写真向けの説明や機種の倍率表記だけを根拠に、今回のProRes＋Apple Log動画で引き伸ばしがないと断定しない。

「引き伸ばしなし」は「完全無劣化」「最良画質」と同じ意味にしない。ズーム中の画質と停止後の画質は別に評価する。

手ブレ補正による撮影範囲の変化とズーム中の補正維持は第18.1.1節に従い、構図予告と停止支援の設計・検証にも含める。

## 9. レンズ切替の連続性

### 9.1 優先方針【確定】

Smooth Lens Switchでは、ISOの数字を完全に不変にすることより、切替時の見た目に違和感が少ないことを重視する。

### 9.2 補正の境界【方針合意／要技術検証】

| 項目 | 動作方針 |
|---|---|
| 通常時 | ユーザーの手動ISOを維持 |
| 切替中 | 切替差を減らすため、限定的なISO補正を許可 |
| 切替後 | 補正後の値を維持し、常時Auto ISOへしない |
| シャッター・FPS | 露出合わせのために勝手に変更しない |
| WB | 録画中のロック方針を崩さない。色の連続性の処理は別途検証 |
| 表示 | 実際に適用されているISO・カメラなどを偽らず表示 |

元のレンズへ戻した際のISO、補正の上限、手動ISOを操作した後の基準更新は未決。

絞りを合わせるだけで、明るさ・色・ピント・画面位置・録画継続がすべて自然につながるとは保証しない。レンズ切替を優先して録画を失敗させない。要求条件で両立しない場合の代替動作は検証後に提示する。

レンズ切替先での手ブレ補正の維持は第18.1.1節に従って検証する。手ブレ補正のための無断設定変更を禁止する要求は、本節で合意したレンズ切替時の限定的なISO補正を撤回するものではない。

## 10. 録画形式と保存先

### 10.1 形式【確定／対応可否は要検証】

| 位置づけ | 希望する形式 |
|---|---|
| 一段上 | ProRes 422＋Apple Log |
| 標準 | ProRes 422 LT＋Apple Log |
| 一段下・容量優先 | ProRes 422 Proxy＋Apple Log |

基本は4K・24／30fps・iPhone内部保存。上位と下位を一段ずつ選べる構成とする。個々のコーデック・色空間・フォーマットの組合せが使えるかを実装前に確認する。

標準の4K・24／30fps・ProRes 422 LT＋Apple LogがiPhone 18 Proの実機で両立しない場合は、別形式へ黙って変更しない。制約と代替形式を提示し、標準要件を見直すまで達成済みとみなさない。

### 10.2 原本と軽量版の保存先【確定】

| 保存場所 | 保存するもの | 原則として保存しないもの |
|---|---|---|
| iPhoneのFrameRelay内 | 撮影したProRes＋Log原本、サムネイル、管理情報 | 同じ軽量版の恒久的な別コピー |
| iPhoneの「写真」 | Mac miniで生成して取得したRec.709軽量版 | 撮影直後の重いLog原本 |
| Mac mini | 改変しないProRes＋Log原本、Rec.709軽量版 | Rec.709高品質版を常に追加生成したもの |

原本はFrameRelayから見られればよい。「写真」で原本と軽量版を二本並べる仕様にはしない。

iPhoneに原本がまだある状態で軽量版を「写真」に保存することは許容する。原本と軽量版が一時的に端末に共存することと、同じ軽量版を二重に恒久保存することは区別する。

### 10.3 外部保存【候補】

外部SSDは拡張候補。通常用途は内部保存が基本であり、外部SSDを常時装着することは要件にしない。外部SSD対応の優先度と、接続・切断時の動作は別途決める。

## 11. 録画体験とライブラリ

### 11.1 閲覧【確定】

iPhone側はサムネイル一覧と単純再生を中心にする。本格的なタイムライン編集、お気に入り、細かなタグ付けは現時点で必須ではない。

撮影原本はFrameRelayで閲覧し、Mac miniの軽量プレビューもFrameRelayから確認できるようにする。軽量版を取得して「写真」へ保存した後は、「写真」から普段の動画と同様に見返せるようにする。

プレビュー確認と「写真」への保存は別の操作・状態とする。第13節の原本削除は、「写真」への保存を待たずに行える。

### 11.2 一回の撮影を一つの項目として扱う【設計案】

原本と軽量版を別々の撮影として一覧に並べず、一つの項目に保存先と処理状態を表示する。

```text
クリップのサムネイル / 撮影日時 / 録画時間

端末の原本              あり／削除済み
Mac miniの原本          未転送／転送中／検証中／検証済み
軽量プレビュー          未生成／生成中／確認可能／生成失敗
ユーザーの確認          未確認／確認済み
「写真」への軽量版保存    未保存／処理中／保存済み／確認が必要
```

表示名やデータモデルはまだ実装指定ではない。原本をiPhoneから削除した後にも、撮影記録・Mac miniの保存状態等を残す方向で設計する。

### 11.3 操作と対象範囲【詳細未定】

録画終了後に毎回保存確認画面へ移らず、次のクリップを撮れる画面に留まる案。保存・サムネイル生成・解析によって次の撮影を不必要に待たせない。

録画停止後の保存途中に中断・再起動した場合も、正常保存、部分保存、保存結果不明、失敗を区別する。保存未確認の動画を正常保存済みとして表示しない。ファイル救済の成功を必ず保証する要求ではない。

原本削除後のアプリ内再生元、「写真」への読み取り権限がない場合の表示、オフライン時の見返し方は、機能設計で決める。「写真」に軽量版を保存する前にiPhone原本を削除した場合、オフラインでは動画を見返せないことがあり得るが、確認記録が有効なら削除を許可する。再生し直すためのWi-Fi接続や「写真」への保存を削除前に強制しない。アプリ内再生のためだけに同じ軽量版の恒久コピーを追加することは標準案にしない。

写真アプリやBlackmagic等で撮った動画の汎用的な取り込みは初期版の対象外。Mac miniにある既存MediaVault動画の原本は開発中のRec.709変換・プレビュー試験に使用する。FrameRelayからの転送試験にはFrameRelayで新規撮影した動画を使う。一般的な過去動画移行機能や旧「写真」原本の削除機能は作らない。試験データはリリース前に整理する。初期版の個別・複数・一括選択の範囲は機能設計で決める。

## 12. Mac miniへの転送と軽量版の生成

### 12.1 転送開始【確定】

撮影後、一覧からユーザーが手動で転送を開始する。録画終了をきっかけに、まだ指示していない原本まで勝手に転送しない。

転送はWi-Fi接続時だけ手動で開始できる。Wi-Fiから外れたらモバイル回線で継続せず、状態を保持して待機する。Wi-Fi復帰時の再開方法、Tailscale等の通信経路・認証・接続先設定は既存実装と照合して決める。背景実行・画面ロック後の継続を保証したことにはしない。

このWi-Fi制限は、原本転送、軽量版ダウンロード、軽量プレビューのストリーミング・一時取得を含む、動画本体の送受信すべてに適用する。すでに端末へ取得済みの動画の再生は対象外。状態確認等の小さな通信までWi-Fiに限定するかは、後続の機能設計で決める。

### 12.2 Mac miniで残すもの【確定】

| 成果物 | 用途 | 方針 |
|---|---|---|
| ProRes＋Log原本 | Final Cut Pro等で編集する素材 | 撮影ファイルを改変・上書きせず保持 |
| Rec.709軽量版 | iPhoneでの確認・鑑賞 | 原本から自動生成し、プレビュー・取得が可能 |

Rec.709高品質版は不要。v0.1の三種類保存案を、二種類へ変更する。編集にはLog原本を使うため、Rec.709高品質版の生成を原本削除や処理完了の条件にしない。

### 12.3 軽量版の仕様

| 項目 | 方針 | 状態 |
|---|---|---|
| 色 | 撮影したLog形式に対応する標準的なRec.709変換 | 確定 |
| 将来の色変更 | 好みのLUTに切り替えられる設計 | 確定 |
| 解像度・コーデック | 1080p・HEVCを候補とする | 候補。実サンプルで評価 |
| フレームレート | 撮影時の24／30fpsを維持。無断で変換・補間しない | 確定 |
| 向き・構図 | 元の向き・縦横比を維持。勝手に切り抜かない | 確定 |
| 音声 | 残す。無断の消音・ノイズ除去・音量補正をしない | 確定 |
| 撮影日時 | 元の撮影日時を引き継ぐ。ダウンロード日時に置き換えない | 確定 |
| 追加の自動補正 | 標準色変換とは別に、クリップごとのWB・明るさを勝手に補正しない | 確定 |
| 圧縮の詳細 | ビットレート／品質設定、ビット深度、音声コーデック等 | 技術設計・比較試験で決める |

解像度を縮小しても、縦動画・横動画の向きと構図を壊さない。色変換は、単に色空間名のメタデータを変更して済ませず、実際の映像変換と再生時の見え方が整合することを検証する。

### 12.4 LUTを変更できる構成【方針合意／詳細未定】

当面の標準変換を使いつつ、将来は変換設定を差し替えられるようにする。Log原本を上書きしない。

変換に使用したLog形式・設定・LUTの版等を管理し、必要な場合に原本から再生成できる構成を案とする。標準のLog変換を含むLUTと、変換後の映像へ味付けするLUTを混同して二重変換しない。

LUT選択の画面、変更を今後の動画だけに適用するか既存動画にも適用するか、再生成した軽量版の「写真」での置換方法は未決。重複を避けるために、ユーザーの写真を無断で削除する仕様にはしない。

## 13. iPhone原本の削除

### 13.1 目的と基本方針【方針合意】

iPhoneの容量を先に空けられるようにする。軽量版を「写真」に保存する前でも、必要な確認が済めば、重いiPhone原本を削除できる。

削除候補になったことと、実際に削除することは分ける。自動で消さず、ユーザーの削除操作を必要とする。原本を必ず先に削除させるという意味ではなく、軽量版取得との順序を強制しない。

### 13.2 削除の条件

| 条件・操作 | 扱い |
|---|---|
| Mac miniへの原本保存と整合性検証 | 必要 |
| Apple LogからRec.709へ変換済みの軽量版 | 必要。未変換プレビューは条件を満たさない |
| FrameRelayでの上記軽量プレビューの再生と明示確認の記録 | 必要。全編再生は要求しない |
| ユーザーによる原本削除操作 | 必要 |
| 削除時のMac mini再接続 | 不要。上記の保存・検証・Rec.709変換・明示確認の記録があることを条件とする |
| 別のディスク等への追加バックアップ完了 | 必須にしない |
| 軽量版をiPhoneの「写真」に保存 | 必須にしない |
| Rec.709高品質版の生成 | 不要。生成機能そのものを要求から外した |

保存・整合性検証の記録、Rec.709変換済み軽量プレビュー、ユーザーの明示確認は、削除対象と同一の撮影原本、およびユーザーが実際に確認した同一の軽量プレビュー映像に対応していなければならない。対応関係が不明なら削除候補にしない。映像が変わらない再ダウンロードだけでは確認を失効させない。

再変換による新しい軽量版の生成と、確認済み軽量プレビューの差し替えは分ける。新版の生成は可能だが、確認済み版の差し替えは、対象端末が旧確認の失効を認識し、その状態を永続保存したことを確認してから確定する。失効を保存した後は、新版の明示再確認まで原本を削除できない。

端末が旧確認の失効を保存する前にオフラインになった場合は、確認済み版をMac mini側だけで無通知に差し替えず、差し替えを保留する。失効保存前の保留中は旧版とその有効な確認記録を維持し、ほかの削除条件を満たすなら、その記録に基づくオフライン原本削除を許可する。端末が失効を保存したことをサーバーが確認できない場合も、差し替えを確定しない。すでに失効を保存した端末では、通信切断や差し替えの保留によって旧確認を有効に戻さない。この順序を成立させる同期・版管理の具体的な方法は後続の設計で定める。

「Mac miniに保存されたらそれでいい」は、追加バックアップを必須にしないという決定。整合性検証、Rec.709変換済み軽量プレビュー、明示確認まで省略する決定ではない。MediaVault側で未変換Apple Logプレビューの確認によって削除候補になっても、FrameRelayでは上表の条件を満たした扱いにしない。

原本削除後の正本はMac mini側とする。別のバックアップが自動で存在するとは扱わず、バックアップ未作成だけを理由に削除候補化を禁止しない。

オフライン削除の根拠は、端末が最後に取得した保存・検証の記録であり、削除時点のMac mini原本の存在を再確認した結果ではない。オフライン中に発生したMac mini側の原本消失など、端末が未取得の変化は削除時に検知できないことを許容する。「安全な削除」はこの保証範囲と前述の条件に基づくものであり、削除時点の外部保存状態を保証する意味ではない。

### 13.3 軽量プレビュー確認と「写真」への保存を分ける

```text
原本の転送・保存検証
    ↓
Rec.709変換済み軽量プレビュー生成
    ↓
アプリ内で内容を見て明示的に確認し、記録
    ↓
iPhone原本を削除してよい候補になる
    ↓
ユーザーが原本を削除可能

※軽量版の「写真」への保存は、これより前でも後でもよい
```

アプリ内確認をストリーミングで行うか、一時ダウンロードで行うかは未決。どちらも動画本体の送受信は第12.1節のWi-Fi制限に従い、Wi-Fi切断時にモバイル回線で継続しない。端末へ取得済みの動画はWi-Fiなしでも再生できる。

表示・再生だけで自動的に「ユーザー確認済み」にはしない。全編再生を必須にせず、内容を見たユーザーの明示操作を記録する。撮影プレビューや構図予告の閲覧はこの確認に含めない。確認操作の文言・見た目は後続のUI設計で決める。

### 13.4 実装前の確認事項

整合性検証の方式、確認するメタデータ、確認済み状態の保存先、再変換時に端末の失効保存を確認してから差し替えを確定する同期・版管理、再試行や再インストール時の状態は既存実装を調べて決める。第13.2節の失効・差し替え順序と保証範囲は要求として維持する。同一原本・同一軽量プレビュー映像に対応する保存・整合性検証、Rec.709変換、明示確認が有効と記録されていれば、削除時のMac mini接続や軽量プレビューの再生は要求しない。確認後にWi-Fiが切れただけなら削除可能な状態を維持する。いずれかの記録や対応関係が不明・欠落・失敗なら、オフラインを含め削除を許可しない。

明示確認の記録途中で中断・再起動した場合、同一原本・同一軽量プレビューに対する確認記録が確定しているか、不明かを区別する。操作を受け付けたことだけで確認済みにせず、記録が不明なら削除を許可しない。旧確認の失効を保存した後に中断・再起動した場合も、その失効状態を維持する。

この会話だけを根拠に、特定の削除候補フィールド名・API名・検証アルゴリズムが既に存在すると断定しない。プレビュー再生の成功を、原本全体の整合性検証の代わりにしない。

## 14. 軽量版の「写真」への保存と重複防止

### 14.1 ユーザーの希望【確定】

取得したRec.709軽量版はiPhoneの「写真」で見られるようにする。同じ軽量版の重複登録と、アプリ内・「写真」での恒久的な二重保存を避ける。

保存はWi-Fi接続時にユーザーが手動で開始する。動画本体の取得は第12.1節のWi-Fi制限に従い、Wi-Fiから外れた場合はモバイル回線でダウンロードを続けない。再開方法は機能設計で決める。取得済みのローカル動画の再生にはWi-Fiを要求しない。

### 14.2 保存処理【設計案】

```text
Mac miniの軽量版
    ↓
FrameRelayで一時ダウンロード
    ↓
「写真」へ保存
    ↓
保存成功を確認し、対応関係を記録
    ↓
不要になったアプリ側の一時コピーを片付ける
```

ダウンロード完了と「写真」への保存完了を分ける。受け渡し中の一時的なコピーは許容するが、成功後も同じ軽量版を二重に残すことは標準動作にしない。

保存状態が不明な場合の一時ファイル処理は復旧設計で定める。失敗したファイルを無制限に残すことも、確認前に再試行に必要な状態を捨てることも避ける。

### 14.3 同じ撮影・同じ変換版の重複管理【設計案】

撮影ごとのIDと変換版の識別情報を使って、原本・軽量版・「写真」の項目を対応付ける。ファイル名だけで同一性を判定することは標準案にしない。

ボタンの連打、通信再試行、アプリの中断・再起動で、同じ軽量版が何本も増えないようにする。アプリや権限の状態により保存結果を確定できない場合は、無条件にもう一本追加せず「確認が必要」とする。

「写真」への保存直後、アプリの管理情報を記録する前に中断した場合も同じ方針とする。再起動後に管理情報がないことだけを理由に再追加せず、保存結果の確認が必要な状態として扱う。

「写真」でユーザーが消した動画を勝手に復活させない。再生成した別LUT版を新規保存するか既存版と入れ替えるかは、別の選択として設計する。

「写真」のアルバム作成の要否、読み取り／追加の権限範囲、再インストールや複数端末での重複防止は未決。アプリ内から「写真」の動画を参照するだけで済むかも検証する。

## 15. 録画と通信の優先順位【確定】

| タイミング | 動作 |
|---|---|
| REC操作 | iPhone側の原本転送・軽量版ダウンロード・軽量プレビューのストリーミング／一時取得を一時停止し、録画を優先 |
| 録画中 | iPhone側の動画本体の送受信を再開しない |
| 録画停止後 | 録画ファイルの保存処理を優先し、再開時点の実行条件を満たす停止中の通信だけ再開 |
| Mac miniで開始済みの変換 | iPhoneの録画と独立して継続 |

通信の停止完了待ちによってRECを不必要に遅らせないことも目標とする。大きなファイルの停止・再開・二重送信防止の方法は、既存転送方式に合わせて設計・検証する。

再開するのは、既にユーザーが開始していた処理に限定する。再開時点でもWi-Fi接続、録画・保存処理の状態、ユーザーによる停止状態等の実行条件を満たすことを確認する。録画中にWi-Fiが切れた場合、録画が停止しただけでは再開しない。ユーザーが停止した処理を録画終了だけを理由に再開せず、まだ指示していない新しい動画の転送も始めない。

録画ファイルの正常保存・異常終了処理が未完了の間に、大きな通信を無条件で再開しない。音声異常からの復旧中などの優先順位は機能設計で具体化する。

## 16. 音声レベル表示とマイク異常への対応

### 16.1 基本方針【確定】

音声付きの録画を基本とする。マイクが使えないと分かっているのに、映像だけの無音録画を続ける方針は採用しない。音声異常が起きたら、それを明確に表示し、解決してから撮る。

「録画を続けなくてよい」は、異常発生前の正常な録画も破棄する意味ではない。正常に撮れた部分は可能な限り保存する。

### 16.2 音声UI【確定／表示詳細は未定】

撮影待機中・録画中に音量をリアルタイム表示する。会話中の「音声のヒストグラム」は、本仕様では音量レベルメーターとして整理する。通常の音量表示と、入力の有効・無効の表示を分ける。

| 状態 | 表示方針 |
|---|---|
| 音声を取得できている | 入力に応じて動く音量メーター |
| 音量が小さい／周囲が静か | メーターが小さい。これだけでは赤い×にしない |
| 初期化・再接続中 | 確認中であることを表示 |
| 音声入力の異常を検出 | メーター付近に赤い×と「音声入力なし」等の理由を表示 |
| 録画が音声異常で停止 | 停止したことと保存結果を明確に知らせる |

使用中の入力名、理由、再試行の導線を近くに表示する案。メーターの本数・単位・更新頻度・音割れ警告は実際の入力構成とUI設計に合わせる。音割れと、音声入力そのものが使えない状態を同じ赤い×だけで表さない。

### 16.3 異常の検出【設計・実機検証事項】

単にレベルがゼロだったという理由で故障と断定しない。権限、中断、入力の有無、音声データの到着、録画への書き込み結果等を確認材料にする。

入力データが届いていても、マイクが塞がる等で期待した音が入らない状態を必ず自動検出できるとはしない。メーターが動いているだけで、音声ファイルの保存成功まで保証した表示にしない。

レベル表示の平滑化、無入力を判断する時間、起動・切替時の猶予、中断との区別、外部マイクの切断判定は実機検証で定める。

### 16.4 録画の扱い【方針合意】

| タイミング | 動作方針 |
|---|---|
| REC前に音声異常が確認されている | 無音のまま開始しない。理由と再試行方法を表示 |
| REC中に音声異常が確認された | 録画を停止し、保存可能な部分を保存。継続録画している表示を残さない |
| 正常に戻った | 録画可能な状態に戻す。ユーザーが再度RECを押す |
| 保存結果が不明 | 正常保存と見せず、部分保存／確認が必要／失敗等を区別 |

WBの安定待ちを省くことと、音声入力が使えないのに録画することは別。起動2〜3秒の目標のために音声を黙って省略しない。

### 16.5 復旧の範囲【方針合意／実装方式は未定】

アプリ全体を自動で強制終了・再起動する仕様は採用しない。異常理由を表示し、「再試行」によって音声処理を立て直す動作を基本案とする。

権限不足なら設定変更を案内し、内部の再初期化で直らない場合は、保存結果を伝えたうえでユーザーによるアプリの開き直し等を案内する。自動で無限に再試行したり、復旧直後に勝手に録画再開したりしない。

どの処理を再作成するか、カメラセッションまで再構成するか、再試行の上限・タイムアウトは技術設計で決める。動画を消す操作やアプリの削除を、通常の復旧手順として組み込まない。

## 17. その他の異常・負荷への対応

### 17.1 優先順位

録画失敗、撮り逃し、意図しない設定変更を減らす。ただし第16節のとおり、確認済みの音声異常では無音録画継続より復旧を優先する。「何が起きても録画を続ける」を最優先ルールにしない。

露出やNDの注意と、録画継続に必要な条件の故障は区別する。露出警告だけで録画を止めない。録画中と保存完了を混同せず、状態を明確に表示する。

### 17.2 例外処理の候補【まだ全項目が確定したわけではない】

| 状況 | 現在の提案 | 機能設計で確認すること |
|---|---|---|
| ND解析の遅れ・不能 | 録画を続け、古い結果を現在のOKとして出さない | 判定の有効期間・表示 |
| 主役を見失う | 数秒間ピントを保持。同じ主役の再捕捉なら追跡に戻り、戻らなければピント保持・控えめな表示・タップで再指定 | 保持秒数、表示と再指定の操作 |
| ズーム・レンズ切替が不能 | 現在のカメラでの録画を優先 | 現在の録画条件での代替動作 |
| 熱・負荷上昇 | まず補助表示・解析を減らし、撮影条件を黙って変更しない | 間引く対象、停止基準、警告 |
| 内部容量不足・書込不能 | 早期警告と保存可能な部分の確定を優先 | 予約容量、開始不可・停止の基準 |
| カメラ・OSの中断 | 実際の停止状態と保存結果を知らせる | 復旧、再開操作、部分ファイル |
| Wi-Fi切断・Mac mini不通 | 原本転送・軽量版取得・軽量プレビューのストリーミング／一時取得をモバイル回線で続けず待機。削除は同一原本・同一軽量プレビュー映像の有効な検証・変換・明示確認記録があれば再接続不要。オフライン中の新版差し替えは第13.2節に従い保留 | 再開方式、状態表示 |
| 原本の検証失敗 | 検証済みにせず、原本を削除候補にしない | 再送範囲と上限 |
| 軽量版変換失敗 | 有効な確認済み版がない場合は原本を保持して削除候補にせず、変換の再試行を可能にする。未失効の確認済みV1を保持し、V2の生成だけが失敗した場合は第13.2節の削除条件を維持する。失効保存後の失敗で旧確認を復活させない | キュー、再生成、重複防止 |
| 「写真」保存失敗・不明 | 未完了として再確認できるようにする | 一時ファイル、権限、保存結果 |

継続・復旧・部分ファイル救済の成功を、検証前に保証しない。手動設定を維持できない構成では、黙って設定を変更せず、制約と代替を示す。

## 18. 撮影補助の初期版範囲と拡張候補

### 18.1 初期版に含める撮影補助

冒頭の「In Scope」と各詳細節を初期版の範囲とする。以下は拡張候補ではなく、初期版で実現・検証する要求。

| 機能 | 現在の扱い |
|---|---|
| Log→Rec.709撮影プレビュー | 固定の標準変換による表示を初期版に含める。Log原本に焼き込まない。第4.3節に従う |
| 音量メーター・音声異常の赤い× | 第16節の基本要求。単なる将来候補ではない |
| 手ブレ補正 | OFFと程度・特性の異なる複数モードを初期版必須とする。以下の第18.1.1節に従う |

#### 18.1.1 手ブレ補正【方針合意／要技術検証】

Blackmagic Cameraのように、撮影場面に合わせて手ブレ補正を選べることを希望する。OFFに加え、程度・特性の異なる複数の補正モードを初期版に含める。「標準／強め／さらに強め」等は例であり、表示名と具体的なモード数は端末・OS・撮影条件の対応確認後に決める。Blackmagic Cameraの名称・内部処理・効果を完全再現する要求ではない。

| 場面・論点 | 要求 |
|---|---|
| 初回の設定 | 標準相当を第一候補とし、その撮影条件で対応することを確認して適用する。非対応なら無条件に適用・代替せず、制約を示して選択を求める |
| 次回以降 | 前回ユーザーが選択した設定を、対応する撮影条件で復元する。以前使えたというだけで異なる撮影条件でも対応済みと扱わない |
| 選択操作 | 撮影待機中に選べればよい。録画中の手動切替は必須にしない |
| 録画中 | アプリ判断で補正の強さ・モードを勝手に変更しない |
| 対応可否 | 現在のカメラ・解像度・fps・コーデック・Log形式等の組合せごとに区別し、非対応モードを有効に見せない |
| 非対応時 | 黙って別モードに置換せず、制約を示してユーザーがOFFまたは他の対応モードを選ぶ |
| 撮影条件の維持 | 補正のために標準の4K・24／30fps・ProRes 422 LT＋Apple Logや手動シャッター・ISO・WBの方針を無断で変更しない |
| 撮影範囲 | 補正による撮影範囲の変化を、撮影プレビュー・構図予告・ズーム停止支援の設計と検証に含める |
| 録画中ズーム・レンズ切替 | 移動中・切替先で選択した補正を維持できるか検証する。維持不能の切替を無通知で実行しない。具体的な制限表示と代替動作は詳細設計で決める |

OFFだけの実装で要件を完了した扱いにはしない。標準の録画条件で希望する補正が成立しない場合は、制約と代替案を提示し、必要に応じて要求を再確認する。モード名を表示できることだけで対応済みとはしない。

選択したモードの実適用を確認し、撮影プレビューの見かけに加え、保存されたLog動画の補正効果・構図・音声同期・録画継続性を確認する。歩き撮り、静止した手持ち、ゆっくりしたパン、ズーム・レンズ切替を代表的な実機試験に含める。補正の具体APIや内部方式はこの段階で固定しない。

### 20.2 受入確認の例【試験設計案・未実施】

| 場面 | 期待する確認 |
|---|---|
| WBが落ち着く前にREC | 安定待ちで開始を止めず、取得した値で固定。音声は省略しない |
| 連続して二本撮影 | 一つ目の最後までWB固定し、待機へ戻った後はAutoで再測定 |
| 録画中にWB取り直し | 明示操作時だけ更新・再固定し、ISO等は勝手に変更しない |
| 撮影プレビューの色表示 | 撮影待機中・録画中に固定の標準Rec.709表示を使える。Log原本には焼き込まれず、撮影プレビューを見ただけで削除前の軽量プレビュー確認済みにならない |
| 手ブレ補正を撮影待機中に選択 | OFFに加え程度・特性の異なる複数の補正モードを選べ、現在の撮影条件での対応可否と実際の適用状態が一致する。録画中の手動切替は必須にせず、録画中にアプリが強さ・モードを勝手に変えない |

| 歩き撮り・静止した手持ち・ゆっくりしたパン | モードの実適用を確認し、撮影プレビューだけでなく保存されたLog動画で補正効果・構図・音声同期・録画継続性を確認する。補正のために録画形式や手動制御の方針を無断で変更しない |
| 補正を選択して構図予告・ズーム・レンズ切替を利用 | 補正による撮影範囲の変化を撮影プレビュー・構図予告・ズーム停止支援へ反映して検証する。録画中ズームや切替先で選択補正を維持できるか確認し、維持不能の切替を無通知で実行しない |
| 標準の録画条件で希望する補正が成立しない | 制約と代替案を提示し、必要に応じて要求を再確認する。OFFだけ、またはモード名の表示だけで初期版要件を達成した扱いにしない |
| NDを濃くする方向と撮影者が判断した代表例 | 撮影意図と評価条件を事前に合意し、案内の方向と理由がその判断に一致する |
| NDを薄くする方向と撮影者が判断した代表例 | 同様に合意した評価条件で方向と理由が一致する |
| 人物と背景の両立が難しい代表例 | 一方だけを無条件に正解とせず、両立の難しさや優先対象を示す |
| 太陽・反射・黒い服が含まれる代表例 | それらの存在だけで不適切なND案内を出さず、撮影意図と対象の状態を踏まえる |
| ND解析が停止・遅延、または評価困難 | 過去の結果を現在のOKとして残さず保留できる。評価可能な上記代表例では有用な案内が必要で、常時判定不能だけでは合格にしない |
| 原本を撮影 | アプリ内に保存され、「写真」に同じ原本が追加されない |
| 録画停止後、保存処理の途中で中断・再起動 | 正常保存・部分保存・保存結果不明・失敗を区別し、未確認の動画を正常保存済みと表示しない。救済の成功そのものは保証しない |
| 原本転送後、検証結果を受け取る途中で中断・再起動 | HTTP送信完了だけで検証済みにせず、検証結果が確定しているかを区別する |
| 変換が成功 | Mac miniには原本と軽量版があり、不要なRec.709高品質版は作られない |
| 同一原本の検証と同一Rec.709プレビュー映像の明示確認が完了 | 「写真」未保存でも削除候補にできる。記録の対応関係が不明な場合、未変換Apple Logプレビューや既存バックエンドの削除候補状態だけでは許可しない。自動削除はしない |
| 軽量プレビューを途中まで見て明示確認 | 全編再生せず確認済みと記録できる。表示・再生だけでは確認済みにしない |
| 軽量プレビューの明示確認を記録する途中で中断・再起動 | 同一原本・同一軽量プレビューへの確認記録が確定しているか、不明かを区別する。不明なら確認済みや削除可能として扱わない |
| V1確認後に端末がオフラインとなり、Mac miniでV2を再生成 | V2の生成は可能だが差し替えは保留し、V1を無通知で差し替えない。V1の有効な記録でオフライン原本削除が可能 |
| 再変換したV2へ確認済みV1を差し替える | 対象端末が旧確認の失効を認識して永続保存したと確認してから差し替えを確定する。失効保存後は再起動しても、新映像の明示再確認まで原本を削除できない。失効保存を確認できなければ差し替えを確定しない |
| 軽量版の初回変換またはV2の再生成に失敗 | 有効な確認済み版がなければ削除不可。未失効の確認済みV1を保持したままV2生成だけが失敗した場合は、V1の有効な記録に基づく第13.2節の削除条件を維持する。旧確認の失効保存後に失敗した場合は旧確認を復活させず、新版の明示再確認まで削除不可 |
| 同じプレビュー映像を再ダウンロードする | 明示確認の記録を失効させない |
| 同一原本・同一プレビュー映像の有効な記録がある状態でMac mini不通 | 「写真」未保存やWi-Fi切断後でも、再接続・再生なしでiPhone原本を手動削除できる。記録・対応関係が不明なら削除できない |
| オフライン中にMac mini側の原本が消失し、端末はその変化を未取得 | 最後の有効な記録に基づく削除は許容される。この時点の原本存在を再確認した表示・保証にはしない |
| 原本の検証に失敗 | 原本がiPhoneに残り、削除候補にならない |
| Wi-Fi切断中に原本転送・軽量版取得・軽量プレビューのストリーミング／一時取得 | モバイル回線へ切り替えず待機する。取得済みのローカル動画は再生できる |
| 軽量版の保存を再試行 | 同じ動画を無条件に複数追加せず、保存状態を確認する |
| 「写真」への保存直後、アプリの管理情報を記録する前に中断・再起動 | 無条件にもう一本追加せず、保存結果の確認が必要な状態にする |
| 原本転送・軽量版取得・軽量プレビューの通信中にREC | 録画を優先し動画通信を停止。停止後は保存処理を優先し、再開条件を満たす既開始処理だけ再開 |
| 録画中にWi-Fiが切れ、そのまま録画を停止 | 録画が終わっただけでは動画通信を再開しない。Wi-Fi接続・録画／保存状態・ユーザー停止状態等の条件を満たしてから再開する |
| ユーザーが通信を停止した後に録画終了 | 録画終了を理由にその処理を勝手に再開せず、まだ開始指示のない動画も転送しない |
| 静かな場所で撮影 | 音量が小さいだけで赤い×・録画禁止・録画停止にしない |
| 明確な音声入力障害 | 赤い×と理由。開始前なら開始不可、録画中なら停止して可能な部分を保存 |
| 音声を復旧 | 使用可能へ戻るが、勝手に録画開始しない |
| ズーム先の予告 | 目標倍率を選ぶと撮影前に到達先の構図の目安を見られる。予告を見るだけでは録画倍率を変えず、表示を原本に焼き込まない |
| 主役追跡中に対象が画面から消える | 数秒間ピントを保ち、同じ主役に戻れなければ別人へ移らず、タップで再指定できる |

この表をもってテスト済みとはしない。単体テストで検証するロジックと、実機・実通信・実ファイルで確認する挙動を分ける。

## 21. この後の進め方

既に参照したMediaVault文書と関連ソースの一部に続き、既存Swiftプロジェクト、RN転送アプリ、Mac miniバックエンド、AI開発テンプレートの規約と実装全体を確認する。Apple Logの現行プレビューは未変換なので、Rec.709軽量版の実現にはバックエンド拡張が必要。要求ごとに「既存実装で使える／変更が必要／新規／未検証」を整理する。読んでいないコードを実装済みとしない。
