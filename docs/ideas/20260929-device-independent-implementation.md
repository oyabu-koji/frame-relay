## Background

実機がない段階でも進められる本体処理が、撮影方式の実機選定や早期通信確認を大きな単位の前提にした計画により待機している。本人が望むのは実機確認の廃止ではなく、都度の実機操作待ちで実装全体が止まらない進め方である。

現状は全機能の実装済みではない。撮影側には純粋規則・契約、保存候補、記録・音声・画面等の探索実装と自動検証の部分証拠がある。バックエンド側はT03の方式非依存契約、T04の隔離環境確認、T05の既存固定配信・Range負荷の部分観測までであり、製品の通信・写真登録・削除・全画面が完成したという意味ではない。T05のRange観測も実再生、実Wi-Fi、背景、失効ACKの成立を証明していない。進捗の正本は各tasklistとし、本書の現状説明を新たな進捗台帳にしない。

六文書と合意済み仕様を横断して、実機なしで可能な実装・自動検証を先に行い、残る実機確認を本人がまとめて実施できる状態にする。変更量と問題切り分けを管理するため、全体を一度の巨大な変更として完了させず、1仕様の下で4段階に分ける。ただし、各段階の実機合格を独立した後段への着手条件にはしない。

- 後続計画・受入担当。既存の部分実装と証拠を再利用し、未実施・不成立・暫定・未接続を混同せず、全21要求・79受入条件を追跡する。

## Scope

1. PRDのP0全21要求（FR-01〜FR-17、NFR-01〜NFR-04）・79受入条件と、撮影・バックエンドの確定仕様を維持した先行実装範囲の整理。
2. 共通永続化、原本管理、ライブラリ・再生、バックエンド連携、写真保存、容量整理・破棄、撮影操作・人物AF・ND・ズーム・表示の、本体処理と接続可能な画面・端末／外部I/O処理。
3. 実機なしで可能なビルド、意味のある単体テスト、Simulator起動・操作／UIテスト、使い捨てデータによるディスク・通信等の結合テスト、コードレビュー。
4. 実装4段階、直接依存ごとの保留、暫定判断の扱い、実装・自動検証・実機確認・PRD受入の別管理。
5. 本人が後で実施する実機確認の対象・操作・期待結果・証拠一覧と、旧仕様・開発規則・計画との整合差分。

「実機なし」は、実機I/Oの成否を推測してよいという意味ではない。実機未確認でも標準SDKや既存契約に基づいて実装できる処理は進め、適用時には未確認・非対応・失敗を正しく扱う。実機から得る事実を固定値や成功応答で置き換えない。

- 外部依存・外部ツールの標準導入、Xcode project／workspaceの生成、iOS Deployment TargetやSwift言語モードの変更。
- 本書保存に伴う別Workflowの暗黙開始。本工程では永続文書、既存Ideas、`.steering/`、アプリコード、稼働環境を変更しない。

## User Flow

### 製品の操作

1. 保存済み設定と対応条件を確認して撮影する。実適用・音声・保存結果を区別し、撮影プレビューや構図予告を原本に焼き込まない。
2. ズーム時は目標倍率を選び、構図予告を見て移動を開始する。目標で自動停止し、途中でもズームだけを停止できる。
3. ライブラリで動画別の原本・転送・軽量版・確認・写真保存・削除の状態を確認する。転送・写真保存・条件を満たす容量整理は複数開始でき、再生・明示確認・破棄は1本ずつ行う。
4. Wi-Fi時に指定原本を転送し、最終保存先の全内容検証後に生成された同一Rec.709軽量版を再生・明示確認する。撮影・保存・回線・本人停止に応じて通信を制御する。
5. 必要なときに「写真」への保存を選ぶ。通常はその保存に必要な追加権限を求める。登録結果の照合が必要になった場合にだけ、理由を示して読み取り権限を案内する。
6. 残す動画は容量整理の条件を満たしたうえで手動削除し、通常一覧に残す。不要動画は対象と消失リスクを別途確認して破棄し、削除成功を照合できたものを履歴へ移す。
7. 削除・写真登録の結果不明は要確認を維持する。管理記録を保持して復旧・照合し、成功を推測したり外部の動画を連動削除したりしない。

### 開発とまとめて行う実機確認

1. 本書を入力に、明示された`$prepare-steering`で4段階の計画、旧タスクとの対応、所有引渡し、文書整合タスク、実機確認票を具体化する。
2. 明示された`$implement-steering`の範囲で実装・検証する。段階ごとに変更を確認し、直接依存が解消した作業へ継続する。各段階で本人の実機操作を待つ手順にはしない。
3. 実機結果が不可欠な作業は、必要な事実・影響範囲・再開条件を記録して局所保留し、独立した本体処理・自動検証・レビューへ進む。
4. 実機なしで進められる範囲の実装状況・検証結果と、残る未接続・仮実装・重大判断をまとめる。本人向け実機確認票を、実装版・実行環境・証拠保存先と結び付ける。
5. 必要な品質条件・試験対象への合意を得た後、本人が実機確認をまとめて行う。結果に応じて修正・再試験し、PRD受入は各ACの全条件を満たしたときだけ判定する。

### DI-02 実装4段階と到達条件

順序は共通基盤を再利用しやすくする標準の進め方であり、全段階を厳密に直列化するものではない。依存しない作業は前段の局所保留中も進める。各段階では本体実装・接続・自動検証の成果と、実機未確認・未採用・未接続を分けて引き渡す。

### DI-03 本体処理、仮実装、未接続の区別

- モック、固定入力、合成媒体、障害注入は、境界や例外を検証する補助に使える。製品処理が実装可能なのに、常に成功するfakeや表示だけで置き換えて完成扱いにしない。
- 本体実装の対象には、必要な永続化、実ファイルI/O、登録・送受信・検証・版管理、実再生、写真登録、削除・復旧、解析・描画・撮影操作との接続を含む。実機が不要なI/Oまでテスト代替だけに限定しない。
- 「未実装」「仮実装／探索候補」「本体処理実装済み・未接続」「本体処理と必要な接続が実装済み」を区別する。後二者にも実機未確認を併記できる。「実機未確認」という表現で仮実装や未接続を隠さない。
- Simulatorや試験データで正常だった保存を、製品の実撮影原本が正常保存された証拠にしない。未確認の実原本・未適合の変換・未確定の登録に成功を注入しない。試験専用の経路・データと製品の事実は識別可能にする。

### DI-04 単一正本と旧計画からの所有引渡し

共通store、原本保存・復旧、原本内容の対応、共有Port、組み立て箇所は単一の責任範囲で扱う。撮影と連携が同じ情報を別々の正本へ保存したり、新計画が既存処理をコピーして別実装を作ったりしない。

後続計画では旧P／Tタスクと新タスクの対応、再利用する実装と証拠、変更担当、所有ファイル、引渡し契約・時点を明記する。同じファイルを複数担当へ同時に割り当てない。旧タスクの履歴・未実施条件を保持し、先行部分を分離したことだけで旧タスク全体を`done`へ変更しない。

### DI-05 原本削除後の表示と管理記録

- 容量整理の削除成功後は通常一覧に残す。原本がないことと、軽量版・明示確認・写真保存の状態を分ける。未取得の軽量版をオフライン再生可能と表示しない。
- 不要動画の破棄成功後は履歴へ移す。履歴は破棄した原本を別の場所に保持するゴミ箱ではなく、復旧・状態照合・重複防止等に必要な管理記録である。履歴への移動を原本の改名・移動・隠蔽だけで実現しない。
- 管理記録の保持と動画本体の削除を別に扱う。必要な対象・目的・操作・内容対応・削除結果・保存検証／確認／写真登録等の記録を、一覧から消したことやキャッシュ回収に伴って失わない。
- 削除成功は実ファイルと管理記録の照合で確定する。要求受付・画面遷移だけで成功にせず、削除結果不明は要照合として見える状態を維持する。正常破棄の履歴へ紛れ込ませない。
- 容量整理と破棄の安全条件・本人操作・単数／複数の範囲を維持する。どちらもFrameRelay内の対象iPhone原本だけを削除し、Mac miniや「写真」の動画を連動削除しない。

### DI-06 「写真」の権限と結果不明

- 通常は追加権限だけを、本人の保存操作に必要なタイミングで求める。撮影起動時に無関係な写真権限を一律要求しない。
- 登録結果不明などで照合が必要なときに、必要な理由と対象操作を示して読み取り権限を案内する。読み取りを認めない選択を、写真への無条件再追加や撮影不能へ置き換えない。
- 拒否、限定アクセス、対応関係不明等で照合できなければ要確認を維持する。読み取り権限があっても照合成功を保証せず、見つからないことだけで未保存と断定しない。
- 登録意図、取得完了、Photosへの追加結果、管理記録の確定、写真側の現在存在を分ける。登録直後の中断・再起動や同一版の再試行でも、記録欠落だけを根拠に再追加しない。
- 写真権限の不足は該当する保存・照合に限定して扱い、撮影等の関係のない機能を止めない。本人が写真側で削除した動画を自動復活させず、不要な恒久コピーも残さない。

### DI-07 ズーム操作と変更可能な評価設定

- 操作は「目標倍率を選択 → 構図予告 → 移動開始 → 目標で自動停止」とする。途中停止もできる。ズーム停止と録画停止は別の操作として識別できるようにする。
- 予告だけでは実倍率を変えず、予告表示を原本へ焼き込まない。予告が古くなった場合は、現在の倍率・カメラ・補正等に対応する有効な予告と区別する。
- 近傍の適した倍率への停止支援を維持する。整数倍率という理由だけで高画質を保証せず、候補が未確認なら確認済みの停止位置として表示しない。実画角・補正・切替・停止前後の画質の確認を残す。
- 速度・精度・吸着の許容差は変更可能な設定として処理から分離する。暫定値には目的・根拠・適用範囲・設定版・変更箇所・未採用であることを記録し、実機評価で採用した値とは区別する。
- 本書は数値、吸着方式の詳細、ユーザー向け詳細設定画面の追加を決めない。暫定値で制御と試験を進められるが、滑らかさ・停止精度・画質の合格や製品採用は実機評価と事前合意に基づく。

### DI-08 撮影・解析・変換で維持する境界

撮影は希望値、能力照会、実適用、実機評価済み条件を分け、未確認を対応済みにしない。人物検出待ち・ND警告・WB安定待ちだけでは必要な記録条件を満たすRECを止めない。静寂と確認済み音声障害を分け、障害時の開始抑止／停止・保存結果の区別・有限復旧を維持し、音声省略・自動REC・無限再試行をしない。

AFは通常合焦・前後追従、見失い保持・同一主役再捕捉、追跡OFFの人物優先AFまで対象とし、人物選択画面だけで完成にしない。NDは方向・理由の有用な処理を対象とし、常に判定不能にする実装だけで完成にしない。解析が遅い・不確かな場合は過去の結果を現在の確定結果として残さない。

実Logに適合する由来確認済みの標準変換資材がない箇所は、変換処理の完成・Rec.709対応を宣言しない。資材の選定・取得と接続、既知入力の機能試験、品質評価を分ける。圧縮のみ、メタデータ付替え、独自の根拠のない係数、仮画像で標準Rec.709を代用しない。写真保存用と確認用には同じMac mini生成軽量映像を使い、原本を改変せず、品質試験前のG3合意を維持する。

## Non-Functional / Technical Notes

### 検証を省略しない進め方
